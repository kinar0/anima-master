## 1. 已确认的产品决策

| 项目 | 已确认要求 | 实施时不得误解为 |
| --- | --- | --- |
| 普通输出 | 保留当前 tags 与英文自然语言混合的七字段输出 | 全面改成纯 tag，或重做普通输出协议 |

## 4. 工作包 A：名词映射只作模型参考

**先完成本包，再让大词库正式参与生图。** 仅扩大词库而保留强制标签通道，会放大误匹配影响。

### 4.1 目标行为

- 普通模式和 -r 继续收到本次命中的“原文词 → canonical tag”参考。
- 任务书明确：参考可能存在歧义，模型结合原文、否定、归属、可见性决定采用；允许不使用，允许自然语言表达。
- 缺少独立 tag 不补入任何全局/角色字段，不触发模型重试，不阻断提交。
- 词库开关继续控制是否匹配和注入，关闭不删除数据。
- 只注入当前请求命中的条目，不把几万条词库常驻写入任务书。

### 4.2 必须追踪的通道

当前重点入口包括：

- `DanbooruResolver.matched_term_mappings_for_prompt`。
- `cached_term_mappings_for_prompt` 及其 `confirmed_tags` 消费者。
- `explicit_term_tags`、`semantic_required_tags`、`required_core_tags`、`structured_extra_tags`。
- `build_wardrobe_authority(... explicit_term_tags=...)` 及词汇命中对衣柜允许集合的影响。
- `missing_term_tags`、`danbooru_term_fallback_tags`。
- NAI 的 noun_mappings 与 `missing_nai_noun_tags`。

不能只删 missing_term_tags 的末尾追加就宣告完成。词汇匹配本身不能经其他列表变成 hard tag、选择衣柜、建立角色身份或替模型决定归属。来自用户原文意图、已确认身份、命名套组和服装补丁的独立证据仍按既有权限处理。

覆盖诊断可以保留，但只记录事实；缺少独立 tag 不代表含义未表达，更不能作为修改提示词的依据。旧字段可保留为空或做明确兼容，避免把“未补入”伪装成“补入成功”。

### 4.3 验收

- 错误匹配，模型不采用：最终不复活该 tag。
- 正确匹配，模型未写：按本次取舍不自动恢复。
- 模型用自然语言表达：不额外强制独立 tag。
- A 的服装参考不被补到全局或 B；共享要求仍由模型按原文表达。
- -r 的全局或角色遗漏参考仍可提交，结构损坏另行处理。
- 开关关闭时不匹配、不注入；raw/# 直通行为保持。

## 5. 原工作包 B：直接利用 Toolbox 词条填充名词翻译（已废止）

**本节仅保留历史设计，不再是实施指令。** 用户已要求撤回全量导入，下一阶段按《中文口语词库质量改进与新对话交接》先建立评估集、审查现有词库并制作小规模口语候选；不能继续按以下旧流程导入整个 general 区。

### 5.1 首批范围

读取 `tags_index_v2.json` 的 general 区，合并 zhFull、zhShort、zhNick、zh 为“alias=canonical_tag”。角色、作品、画师库不进入名词翻译；不要直接把 tag_gloss 的完整解释句当触发别名。

允许多个不同别名指向同一 tag。现有板块保存单值映射，因此同一个 alias 指向多个 tag 时，首批跳过并列入冲突清单，不按热度、字段顺序或最后写入者任意选择。

释义、误读和辨析是可选的后续辅助数据，不作为本次批量导入的前置大工程。不要转成重新调用 DeepSeek 翻译、逐批复核已有词条的流程。

### 5.2 导入流程

1. 读取数据，记录版本、来源文件哈希和提取规则版本。
2. 纯本地提取、格式校验和去重，产生完整候选及原因明确的跳过记录。
3. 与当前生效的完整名词词库合并；已有人工映射优先，相同映射去重，冲突不覆盖。
4. 预览新增数、已有数、歧义数、冲突数、无效数及合并总数；区分“已存在”和“冲突”。
5. 保存词库快照和导入清单，再通过现有持久化路径应用，热更新解析器；不得为了方便覆盖整份插件配置。
6. 验证页面、配置与运行时读取的是同一份全量数据，搜索和分页展示正确。

导入前后若 revision 或人工词库变化，应基于最新完整状态重新合并，避免覆盖并发编辑。重复执行对未改变数据应幂等；对用户后来修改的映射继续以当前值为准。

首版无需额外创造独立词库产品或常驻第二套映射源。可采用一次性本地导入器并复用页面保存逻辑；具体入口依实施时权限和持久化能力决定。

注意：当前 DeepSeek 批量翻译导入器对别名采用 2–30 字符限制，而词库页面的名称校验允许到 80。上述候选统计按 2–80 计算；不能直接复用旧批量导入过滤后仍声称候选全部可导入。实施时以选定持久化入口的实际规则重新统计，并保留被过滤原因，不为凑数量随意放宽既有校验。

### 5.3 容量、性能与恢复

- 超过 50000 条时明确报告，避免截断或部分静默写入。不能擅自提容量或降低过滤标准以凑数。
- 页面跨页修改、全量搜索、保存以及配置同步须适用于扩容后的真实规模。
- 测量一次请求匹配几万别名的成本；有必要再增加缓存或索引，避免每次生图重复解析并建立大量正则。保持最长重叠、其他位置独立短词和否定过滤语义。
- 导入清单记录实际新增、原值和来源，恢复时只撤销仍与导入值一致的新增条目；不要恢复整份旧配置并覆盖导入后用户的其他修改。
- 展示或导入记录不得输出 API key 等无关配置。

### 5.4 验收

- 小样本验证提取格式，再以 Release 全量数据做本地规模验证；无需让模型审核每个词。
- 长/短别名、空白、大小写、格式非法、重复、同词多义、人工冲突均有确定结果。
- 重复导入无重复新增；用户编辑和 revision 变化不被覆盖。
- 保存/重载/热更新后数目一致，50000 上限覆盖“已有+新增”。
- 大词库只增加匹配覆盖，不增加模型调用轮数；任务书只携带请求命中条目。
- 与 Anima CSV 的覆盖差作为统计报告，不暗中变为 NAI 路径的导入禁用规则。

## 6. 工作包 C：背景交给模型判断，消除程序反向改写

### 6.1 期望规则

默认使用 simple background 与 white background。原文明确或隐含需要环境时，允许模型补足相关场景；明确简单/白底时遵循用户要求。补足应服务于用户主题、事件和动作，不能默认附加雨夜、夕阳、花园等装饰设定。

用户指出现有实践中“背景词是否出现”经常与设想不一致。因此不能再以“没有地点关键词”或某个局部正则结果自动强制白底，也不能根据背景标记自动删除模型设计的环境。

将此规则写入现有 writer 的背景指引；普通模式与 -r 一致。最终背景选择交给模型，宿主不因该判断另增模型调用。控制标记可用于诊断或兼容，但不得间接恢复强制补删。

### 6.2 审计范围

核对 system、BACKGROUND_POLICY_TEMPLATE、background marker、`enforce_user_background_intent`、generated_scene_selected、default portrait 标签与 prose 清理、`build_final_prompt` 默认背景拼接，以及 -r 完成后的背景修正。

宿主最终组装不能在模型没有输出白底时又补入，也不能在模型选择环境时用旧规则删掉。模型本身输出冲突背景主要由同次写作的一致性规则处理；不要把新固定场景白名单写成通用语义判定。

只修改背景相关规则，不借此全面重做七字段、普通 system 文案或 Nltags 策略。人为配置和 # 中明确写入的标签仍遵循原有直通/配置契约，不将其与自动兜底混淆。

共享辅助函数可能被旧多人、图生图、Turbo 使用。先核对影响；此次主要目标是普通优化与 -r，不顺带重写兼容模式或低 CFG Harness。若必须触及 Turbo，按 AGENTS.md 阅读其额外文档并单独验证。

### 6.3 成对验收

| 原文 | 写作预期 | 程序必须保证 |
| --- | --- | --- |
| 女孩穿婚纱微笑 | 默认简单白底 | 不由主机另创造教堂/花园 |
| 两人在教堂举行婚礼 | 教堂场景 | 不追加自动白底，不删场景 |
| 两人放学后走回家 | 可补足回家途中环境 | 不因无地点词强制白底 |
| 女孩坐在椅子上 | 道具不必扩展成完整房间 | 不用椅子关键词强判场景 |
| 两人放学后回家，简单白底 | 显式白底优先 | 模型任务书保留这一要求 |

单元测试用受控模型输出验证宿主不补删；真实模型样本再评估语义判断。不得用预写回复通过测试来宣称模型已经总能理解隐含场景。

## 7. 工作包 D：NAI -r 在第二阶段直接输出完整规划

### 7.1 目标调用链

```text
共同入口、原文与参考上下文
  → LLM1 原文角色/服装/修改意图
  → 本地身份、衣柜、外貌权限及命中的词汇参考
  → 按输出模式选择第二阶段任务书
      普通：现有七字段混合输出
      NAI -r：全局提示词 + 逐可见实例提示词 + 坐标 + 互动方向
  → 对模式对应结果做结构和既有权限检查
  → 既有工作流提交与交付
```

“一次返回”仅指第二阶段一次完成写作和布局，LLM1 保留。正常 -r 不再先调用普通七字段 writer，再调用完整拆分 writer。必要的结构修复不算正常主链，不得把旧第三阶段藏在“验证”里继续运行。

### 7.2 上下文与输出

- 提前解析实际后端、模型、尺寸和角色实例上限，给第二阶段传实际画布与比例。
- 直接提供原文、canonical 身份绑定、逐角色衣柜与修改、外貌 replace/additive/omit、参考上下文以及名词参考。
- 不要求先生成一份扁平完整提示词作中间输入，不把普通七字段任务书和 NAI JSON 任务书同时塞给模型。
- 复用现有 NAI 计划外形及工作流消费者，减少协议变更；确需调整字段时显式更新解析、摘要、消费者和测试。
- 每个可见实例单独一项。同一身份在不同格子的动作、服装和位置可以不同，不能按名字去重。
