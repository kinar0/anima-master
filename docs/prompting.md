# 提示词与角色画风

## 严正警告：不要随便精简或简化给 LLM 的提示词

> **给后来的维护者、AI 代理，以及用户本人：不要因为提示词看起来长、啰嗦、重复，或为了减少字符/token，就随意精简、简化、合并、改写或删除给 LLM 的提示词。提示词是功能实现的一部分，不是可以按文案审美随手压缩的说明文字。**
>
> 本项目已经实际发生过：重构和精简后职责遗漏，中文描述被弱化为可选，位置与 tag 分配复核不足，普通身体状态被分给错误人物。补回一句泛泛的“准确理解并检查”不能替代原来明确的职责、边界、反例和输出要求。**不要再用功能退化换取表面简洁。**

用户本人以后如果只说“整理一下”“太长了”“精简一下”“去重”“优化提示词”，应默认理解为**在保留全部功能、约束强度和现有工作流的前提下整理**，不代表授权删除功能、降低要求或重新设计调用链。执行者必须说明具体改动及影响；用户也不要仅凭字数变少、读起来顺口就认定修改更好。用户明确要求改变某项行为时，按该具体要求处理，并写清契约变化。

确实需要调整时，必须遵守以下要求：

1. **先找基线，再逐项对照职责。** 阅读当前工作流文档、实际拼装后的 system/user/修复提示及必要的 Git 历史，列出旧要求在新文本中的对应位置。核对人数和实例、身份与服装证据、用户修改优先级、可见性、中文实际输出、全局/逐人作用域、位置和接触、`source# / target# / mutual#`、普通动作的身体所有者、逐项自审与修复职责。不能只凭聊天摘要或记忆判断“都还在”。
2. **不要把具体规则压成空泛口号。** “完整表达”“正确分配”“检查冲突”不能替代具体边界；必填不能变成可选，实际 `prompt` 的要求不能挪到不会进入生成文本的分析字段。不能因表面重复，就删掉不同阶段、不同优先级或修复调用中各自需要的约束；示例和反例也不能未经核验就当作废话。
3. **以实际行为验收，不以长度验收。** 修改后核对模型原始回复、后处理结果和最终进入转换节点的文本，并覆盖不同人物、不同衣物、多人共享条件、动作换向及不能匹配的反例。涉及模型语义的改写，纯替身测试、合法 JSON、配对通过或一次成功均不能证明等价；应在已有授权范围内做真实模型回归，明确未验证的范围，不能把“更短”或“测试数量更多”当成功标准。
4. **保留可审查、可回退的记录。** 提供职责对照、实际差异与验证证据，同步更新相关文档；旧审计中的精简记录和字数下降不是后续删减的授权。定位到功能遗漏或尚不能证明某项要求可删时，保留或补回该要求，不继续凭感觉压缩。

## NAI 原生文字

NAI 工作流支持 `牌子写着“原文”`、`角色说：“台词”`、`角色：“台词”` 和按画格/位置标出的旁白，以及放在最后的 `Text:` 原文尾段。原生文字优化请求自动复用已有逐实例 LLM2，JSON 增加 `text_regions` 绑定出现编号、画格、具体角色实例或无主文字、实际位置说明；不是先写普通七字段再进行第三次拆分。同名角色在不同格子分别建实例，相同台词重复出现也有不同编号。对白/内心独白进入对应实例的 `Text:` 尾段；旁白、画外对白和无主物件文字进入带明确画格和位置 prose 的 base 尾段。没有文字需求的普通七字段与 `-r` JSON 不变。原文不翻译、不截断、不按 tags/权重解析；原始位置由宿主从编号保存，不要求模型重新抄写整句来源。缺失/重复编号、无效实例、跨格复用和作用域错误在同一结构修复中重试一次，仍错误则停止，不压平到 base。中文需 V5，V4/V4.5 仅支持英文。raw/关闭优化只保留显式原生尾段，已有 `comic_dialogue_enabled` 开启时自动对白仍用原排字流程。细节见 [NAI 原生文字生成](NAI原生文字生成.md)。

手工 `#` 现在只在引号与原生 `Text:` 尾段外分隔；文字中的 `C#` 等原样保留。手工 tags 仍插入 `Nltags` 与 `Text:` 之前，不能进入要画出的文字尾段。

文字绑定表有效、但 writer 将已知台词额外复制到错误 prompt 时，按已接受的 owner 表确定性移除越界台词引用（保留其余画面描述），再在正确作用域追加完整位置句和原文尾段；`nai_dropped_text_references` 记录修正。此投影不猜角色或画格，不修复错误绑定本身。没有在 raw 中重复完整画格短语时，最终位置句仍会补入原文已确认的画格；raw 明确写成另一格则要求修复。

## 漫画台词原文排字

配置项 `comic_dialogue_enabled` 默认关闭。开启后，普通文本生图请求中出现明确的 `漫画对话：`、`漫画台词：`、`内心OS：`、`内心OS气泡：` 或 `旁白：` 时，宿主从这些标记下的 `角色：台词` 段复制原文，包括中文标点。没有这些标记时，也识别 `爱音说：“……”`、`祥子心想：“……”`、`爱音：“……”` 等带说话人的引号台词。`正向提示词：` 后的内容仍是画面描述，不会被误当成台词；仅有“表白”等剧情词、匿名引号台词，或“无对话，仅惊吓音效气泡”不会触发排字。无法解析显式标记时，本次任务在提交 ComfyUI 前停止。

提示词优化、角色规划、服装权限及 NAI `-r` 仍运行原有流程。生成完成后，发送前的独立排字模块优先在画面内低细节区域安排气泡；台词较多、较长或画面没有足够位置时，将原文放在图片上方的对白区。气泡位置由画面细节启发式决定，可能覆盖局部画面，也不能保证把一句话对应到多格中的特定人物或画格。原始 ComfyUI 图片不修改；发送排字后的 PNG。NAI 和 Anima 共用这一策略。缺少中文字体、排字异常或文字超过可支持页高时不发送无台词原图；复杂分镜仍建议每格单独生成。

## 自然语言模式

普通 `/anm` 会让聊天模型把自然语言自由发展为完整画面，并整理成 Danbooru tags：

内置普通、多人兼容及 NAI `-r` 任务书已删除所有 `looking at viewer` 相关示例和说明，包括否定式提醒；配置页“自然语言优化模板”的默认值同步更新。已保存的旧内置模板在加载时迁移，自定义模板保留。此改动只清理写作指令，不增加输出 tag 黑名单；模型仍可能自行产生该 tag。用户原文、原样模式和 `#` 手工尾缀沿用原有处理。

用户提示词可用第一个 `#` 追加手动提示词，例如 `/anm 蓝色连衣裙女孩#masterpiece, backlighting`。`#` 后内容不会参与中文语义分析、角色识别或 LLM 优化，而会在提交 ComfyUI 前原样插入程序生成的 Danbooru tags 与 `Nltags:` 之间；没有 `Nltags:` 时追加到末尾。

NAI 工作流可在正文加入独立的 `-r` 开关，例如 `/anm -r 左格高松灯穿校服站立，右格高松灯穿礼服坐下`。保留第一次意图规划和本地角色/衣柜证据；专用第二次 LLM 直接输出全局与逐实例 JSON，不先生成七字段，也不再另调用拆分模型。模型收到本次实际画布的宽高和比例，先分析视角、人物关系与整体构图，再为每个可见角色实例写独立提示词、位置理由和 XY 坐标；同一角色在多个格子出现时各占一个角色框。V5 文生图最多 22 个实例，V4/V4.5 最多 6 个。主机不根据姿势词套固定坐标。按照 [NovelAI Multi-Character Prompting](https://docs.novelai.net/en/image/multiplecharacters/)，base prompt 保留总人数、场景、风格和整图条件；角色框使用无数字的 `girl / boy / other`，并承载该实例的身份、外貌、服装、表情、姿势、动作、物件使用及局部环境关系。`bed` 可以作为共享场景物件留在全局，`lying on bed` 则进入相应角色框。解析器只删除可明确判定为角色实例条件的全局项，不因同一个环境名在角色框出现就删除它；删除结果记录到 `nai_dropped_global_character_tags`。原样/关闭优化模式不执行逐实例规划，因此不能与 `-r` 同用；`#` 后的 `-r` 只算手工 tag，不触发开关。
`-r` 任务书不再要求模型生成画师或质量词，只说明它们由主机补全。全局人数按普通模式的女性、男性、混合组合统计所有可见实例（同名多格也逐实例计数）；角色框只能使用无数字的 `girl / boy / other`，解析器将误放的独立 `1girl / 1boy / Ngirls / Nboys` 等计数项归一为单实例性别词。性别优先遵循用户明确要求与可靠身份资料，不因“书生”等称谓、服装或胸部尺寸自行改变。
中文请求的 NAI `-r` 写作者必须在每个实际角色 `prompt` 中保留简洁但完整的中文描述，覆盖该实例可见的外貌、服装、表情、姿势、动作和关系，不设“一句话”限制；canonical tag 与身份仍使用准确英文拼写。不能只输出英文 tags，也不能用 `source_text`、分析或位置理由中的中文代替实际提示词。先明确中文中的主体、对象和身体部位归属，再据此分配 tags；指代其他人物使用名字或位置，不在本角色框重复别人的外貌、体型或服装。原文仍无法确定所有者时保留原句，不用 tag 猜归属。`source_text` 必须使用原文原语言，不能翻译后再当作原文引用；分析和位置理由可用中文或英文。普通非 `-r` 七字段仍沿用自身语言要求。
全员共穿的命名服装也应分别写在各角色框；当所选套组仍然适用且可见时，实际框内保留已确认的 canonical tag，不能只留中文服装名。直接写作入口把已分类的命名套组、衣柜及稳定外貌证据传给解析器，清理全局误放项，不再只依靠通用服装词形；初稿和文字归属修复稿使用相同边界。该清理不推断穿着者、不补缺失标签，也不把共享床、桌等环境物件一并删除。动作句须明确谁用自己的什么部位接触谁的什么部位；普通身体状态 tag 描述所属角色，不能因其为主动方就把接受方的身体状态写进主动方框。2026-10-17 起，有效配对方向标签已表达的同名动作不再重复普通 tag，完整自然语言关系继续保留。模型在原有同次自审中核对实际 prompt，而不是仅在分析字段中描述正确关系。

普通动作不因方向前缀而自动获准。逐项把普通 tag 当作当前实例自身的状态来判断：身体位置/身体状态描述归属于受影响身体部位的所有者，不是接触肢体的所有者。例如 A 把自己的手伸进 B 的嘴里，有效的 `source#hand_in_mouth / target#hand_in_mouth` 已表达双方关系，两个参与框均删除独立 `hand_in_mouth`（包括普通加权写法），保留中文动作和 B 的 `open_mouth` 等不同状态。处理先降级不确定的方向组，再按各实例剩余方向动作的精确规范名去重；不猜同义词，不删除无关第三人的同名普通动作，也不删除自己的手放在自己嘴里等无配对单人动作。未配对方向被移除时，普通动作继续作为原有回退保留。全局同名重复项同样清理，诊断为 `nai_dropped_redundant_action_tags`。此规则明确更新此前“普通动作与方向总是并存”的契约，不增加模型阶段。

### 互动焦点与词汇选择（2026-10-17）

未限定镜头时，写作者先找本图需要看清的特征、表情与接触点，比较近景、斜视和过肩取景，再决定人物朝向与裁切。细小面部互动应让受影响的面部与接触点可辨；主动方可以背向或部分出框，不能为了显示更多档案 tag 优先让主动方露脸、或扩大到全身。对视与相机方向分别表达；明确镜头仍优先。表情不能妨碍接触的物理前提，例如口内触碰不同时要求闭嘴或咬紧牙关，抗拒可用眉眼、身体紧张等兼容状态表达。

所选最终构图还会逐实例复用已有衣柜裁剪，清理继承的画外裙装、鞋袜等组件；各格分别处理，用户补丁仍受原有保护。`nai_composition_omitted_tags` 记录裁剪。写作者同样须只描写本图可见的衣物；程序没有通用中文遮挡理解器。

同一词义采用词库给出的 canonical 拼写，不为修饰或加强意义擅自变复数、换近义 tag；词义确实不同或映射不适用时仍可舍弃或用自然语言。词库继续是参考，不增加强补、硬覆盖或整份重试。共穿校服也不代表共享个人发饰；通用套组的数据本身含个人配饰时应修订数据，不能只让模型对抗错误证据。

**双语输出契约：英文 tags 与中文自然语言必须同时存在。** `global_prompt` 和每个实例的实际 `prompt` 都使用“英文视觉 tags + 原语言完整句子”；中文请求的句子使用中文，但标签层仍使用英文，不能把 tags 翻成中文关键词。只有 `girl`、英文身份名和方向 tag 不算完整英文细节层：本图适用的可见外貌、衣物、表情、姿态、镜头/场景仍要有相应英文视觉 tags；没有可靠 tag 的含义继续用自然语言表达，不为覆盖名词映射而强补。例：`white_shirt, sitting, 穿着白衬衫坐着。` 同时保留两层，`girl, character_a, 白衬衫，坐着` 则没有完成英文细节与中文成句的职责。英文 tags 与中文句子之间用英文逗号明确分隔，不能只用句号把最后一个 tag 与中文粘在一起。中文仅写在分析字段、英文仅由后处理补回档案外貌，都不能代替写作者履行这项契约。

`global_prompt` 同时承载共享 tags 和实际用于生成的关系中文，说明构图、人物位置、谁对谁做什么；不写个体外貌/衣服，不用另一人的特征指代其身份。实例框描述各自状态，整体中文将它们连接成同一场景。接触复核需结合镜头尺度判断身体和肢体是否能够相接，不能把人物摆成互不相干的独立个体，也不套固定坐标。

NAI 后处理对已识别、与档案一致的中英文外貌表达予以保留，不再一律删后补英文。例如“粉色长发灰眼女孩”不应变成“粉色女孩”。复合外貌同时核对已锁定的颜色、长度等维度；冲突或不能确认的受控片段仍按权限过滤，只恢复本次已表达的档案维度。用户修改和 omit 优先；原本没有写出的特征不补齐。身份名和方向标签不送进普通外貌句过滤，已有相同 canonical tag（含权重）不重复补入。

写作者还需逐维度核对 tags 与中文的一致性，覆盖服装状态、表情、视线、动作接触、镜头、背景和照明。未要求时不额外添加柔光、电影光等照明，明确无光时不补灯；明确素颜、无表情、空白背景等状态不擅自润色。默认白底与明确/隐含需要的场景不并列。该判断仍在原有同次写作内完成，不恢复主机背景词门控。
第一阶段偶尔返回合法但不完整的角色名单时，本地已命中的其他角色档案以独立条件参考交给 `-r` 写作者，包括各自稳定外貌与可用衣柜；已明确的借衣/cosplay 来源不升级为可见人物。写作者从完整原文决定哪些实例可见，选中的本地身份再接受逐角色后处理。条件参考不会强迫所有提及的人物出场；无法绑定的明确服装需求禁止恢复默认衣柜，也不把未分类身份放进共享 hard tags。摘要 `nai_local_profile_references` 记录参考行，`nai_bound_local_profile_references` 记录本次真正采用的参考。
启用画师词时，布局模型返回后主机会从当前画师组恢复全局画师串，并替换同名的畸形副本。预置中的嵌套括号加权画师项（如 `(yd_(orange_maru):1.1)`）在最终提示词中按原样保留。
同一身份重复出现且有服装/外貌修改时，NAI JSON 的 `source_text` 引用该实例实际适用的原文片段；共享要求与局部要求分散在不同句子时，可返回片段数组，不得把不连续原文拼成新句。不同衣柜计划用 `anchor_id` 对应本地证据。宿主检查必要证据可在原文中定位，逐实例应用修改，不按同名或数组顺序把左格删改传播到右格；缺少必要归属或证据虚构时停止提交。身份唯一、重复实例没有待区分的修改，或没有匹配的本地计划时，`source_text` 不参与权限选择；不成立的可选引用会被丢弃并记入 `nai_dropped_instance_sources`，不阻断布局。有效本地 anchor、角色身份、外貌及衣柜权限仍独立校验。辅助字段不进入 NAI 文本转换节点。

命中“名词翻译”时，`-r` 布局模型还会收到“原文词 => canonical tag”映射作为词汇参考，根据原文在角色框或全局提示词中表达含义，也可使用自然语言或有效的方向动作 tag。这些映射不是必须逐项齐全的验收清单；遗漏独立 tag 不触发整份布局重试，也不阻断生图。主机只在 `nai_missing_noun_tags` 中记录独立 tag 的覆盖差异，不据此猜测归属或强行补到所有角色。映射本身不记录所属角色，归属仍由模型根据原文判断。
关闭 `danbooru_term_mappings_enabled` 后，普通模式与 `-r` 都不使用这些名词映射。映射数据仍保留，可在服装词库页面重新开启。
独立 tag 覆盖诊断也认可角色框中已校验并实际写入提示词的 `source#tag`、`target#tag`、`mutual#tag`：例如 `mutual#interlocked_fingers` 已保留 `interlocked_fingers`，无需再重复一个普通 tag。自然语言中提到该词、只留在全局的方向标签或被丢弃的畸形标签不计入精确覆盖；该统计不会决定是否生图。
画师组也支持 NovelAI 数值权重写法，例如 `1.2::artist:banpai akira ::` 与 `-0.5:: lips::`。保存画师组和最终拼接时会保留起始权重、内部 `artist:` 及末尾 `::`，不在这些语法冒号前加反斜杠；普通 Danbooru 名称中的字面量冒号仍按原规则转义。
布局阶段的返回还包含构图分析、每人的位置理由和坐标。输出预算按模型角色上限扩展，最多 7200 tokens；角色越多、逐人描述越长，越可能使 JSON 不完整，解析失败会停止本次提交。当前画师组可由配置或本次 `-sN` 选择。
`-r` 布局模型从完整原文判断是否存在可见人物之间的明确动作，不再由拥抱、牵手等固定词组决定是否开放方向 tag。主动方用 `source#hug`，接受方用 `target#hug`；双方对等时两边可用 `mutual#hug`。踢、喂食、扶起等动作也可由模型按语义判断；掀门帘、回头、点头等单人动作应留空。每项 `#` 后只接一个英文 Danbooru 动作 tag；主机校验格式并丢弃畸形项，同时核对同动作 source/target 位于不同实例、mutual 至少两人且不与同实例的 directed 角色冲突。配对不完整、孤立 mutual 或同实例混用 mutual/directed 时，仅移除有争议动作组的方向标签并记录诊断；保留普通动作、中文关系、位置与其他有效配对，不因配对问题重写或停止。动作名只规范化大小写、空白、下划线和连字符；不同名字无法确定为同一动作时，不猜同义词、不补接收者，也不改写动作原文。是否确有互动及方向是否符合原文，由同次写作中的语义复核负责；主机的结构检查不是通用语义验证器。这是 [NovelAI 多角色动作标签语法](https://docs.novelai.net/en/image/multiplecharacters/#action-tags)，与用户输入中第一个 `#` 后的手工尾缀不是同一个处理步骤。

聊天模型会先把自然语言拆成少量语义锚点，区分画面中的目标角色与只提供服装的角色/变体来源，并为作品、服装、动作、道具等提出候选。插件随后一次调用本地 `danbooru-tags` 批量校验：精确命中才成为 hard tag，模糊结果只作候选，缺失概念改写到 Nltags。已确认的服装来源角色会再用有限帖子样本提取高频服装共现，因此 Oblivionis、Mortis 等变体不需要逐个写入插件代码。旧的命名角色联网校正仍作为回退；Donmai 不可用时会自动回退到 Safebooru 只读 DAPI。

第一阶段语义规划 LLM 的 system prompt 可以通过 `danbooru_semantic_system_prompt` 修改。该配置控制逐角色意图抽取，不允许要求模型猜 tag 或生成 lookup；本地匹配发生在其后。它不会替换第二阶段的 `prompt_builder_template`；留空时使用插件内置默认值。

第一阶段的主要职责已经从“为查询列关键词”扩展为“明确谁穿什么”。它必须为每个可见角色输出一条 wardrobe 计划，并把“双方、两人、都、双女主、both、all”等共享服装范围展开到所有穿着者。任务书会明确要求服装修改使用 `upper_body.primary / lower_body.skirt / one_piece.dress / outerwear / headwear / face_accessory.mask / handwear / legwear / footwear / lower_body.all / misc`，不好分类的组件统一放入 `misc`。程序会把常见过去式操作、mask/boots 等普通名称和未知非空槽位归一化，而不是静默丢弃整条 LLM1 修改；精确的原文 `source_text` 会继续交给第二阶段理解。Danbooru 查询临时不可用时仍会执行这一步，只跳过候选验证，避免直接把角色默认衣柜当作保底注入。

## 两次 LLM、角色档案与衣柜

### NAI `-r` 的位置必须支持整组动作（2026-10-15）

位置选择服务于用户期望的构图和动作。专用 writer 先用空间思维在三维中安排人物、道具与支撑面，再按实际画布和用户镜头投影；同一时刻、同一格内的全部动作必须能同时成立。逐项考虑动作双方、身体部位、接触点、身体尺度、朝向、臂展、高低、前后与遮挡，共用人物的多项接触要联合检查，不能先平均分配左右位置、再用文字宣称接触。重叠身体可使用接近或相同的中心；要求分离的群组、独立画格则保留间距，不为了接触而拉近无关人物。屏幕 y 是投影高度，不单独代表深度。

输出仍用原 JSON：`x/y` 是实例可见区域在整张画布上的归一化中心，不是头、手或接触点，分格也不改成格内坐标。通常使用 2–3 位小数，不吸附到十分位或固定网格。安排不支持整组动作时，调整尚未限定的间距、尺度、姿势和取景，保留明确的镜头、左右、分格及裁切要求；确有不可兼容要求时在既有 `relations` 简短注明，不默默省掉动作。`position_reason` 简述位置支持的动作或分离条件。原同次复核再次对照坐标、全局中文与实例文本，不增加模型阶段、字段或宿主姿态规则。

职责对照：旧 `Composition` 的画布/视角/高低/接触/裁切职责全部保留，追加联合可达性、三维到二维投影和连续中心；system 中追加整组动作的空间目标；原 `Writing and review` 追加最终空间一致性检查。原有双语层、人数与实例、身份/服装证据、逐实例修改、可见性、全局/逐人归属、身体部位所有权、方向配对的写作复核保持；2026-10-16 起宿主仅对有争议的方向标签降级，文字归属仍保留一次修复边界。修复调用继承完整任务书和同一 system。

配套 NAI 节点 `CharacterPromptSelect` 的界面步长从 `0.1` 改为 `0.001`，取消后端一位小数取整，范围仍是 `[0,1]`。例如 `0.3427` 经节点与 API payload 保持原值；已有归一化工作流无需改位置。AstrBot 解析和工作流适配本来就传递浮点数，不新增取整。坐标是构图引导，无法保证精确肢体或像素位置；[NovelAI 官方文档](https://docs.novelai.net/en/image/multiplecharacters/)仍注明 V4/V4.5 自定义位置受 5×5 网格限制，传输精度不等于模型空间分辨率。

回归包含近邻/重叠中心、边界值、22 个角色槽及正负 API caption 的精度传递，并以真实 provider 核对双重接触、坐姿/跪姿支撑、无互动分格和同名不同衣物。原始回复、实际任务书、后处理文本保存在 `diagnostics/nai-spatial-review/`；测试仅到提示词与工作流构造，不提交 ComfyUI/NAI 图片，不能据此断言肢体生成正确。

`-r` 的互动主体、对象、方向及必要接触关系须写入相关实例的实际 `prompt`，不能只留在构图分析、位置理由或方向标签中。基于 `7968ae1` 的直接实例 JSON 写作，任务书补回七段原有的七类语义职责：人数、身份、作品、可见外貌、服装/动作/表情/道具、共享视觉条件及连贯自然语言关系。模型在同一次调用内部设计后再复核位置、镜头、格子、高低/前后、朝向、视线、接触和 tag 分配，纠正遗漏或冲突；不生成七段草稿，不增加正常调用轮数或输出字段。方向双方使用同一动作 tag，真正对等的动作才用 mutual；复核后的关系和位置理由记录在既有分析字段。主机另核对方向配对结构，无法确认时只移除有争议动作组的方向标签，不重写或停止；完整动作关系仍由实际自然语言保留。结构配对不能证明动作语义正确。详见 [补齐审计](NAI-r重构后功能补齐审计.md)。

### NAI `-r` 与七字段的共同写作规则

两条路径共用完整的色气表现力指引；服装权限保持同一优先级，NAI 使用末尾的精简英文说明区分已选套装、显式档案与未指定服装时的默认软参考。`sensual_mode_enabled` 与 `sensual_mode_markers` 同时控制普通和 `-r`：在明确要求内增强表情、姿态、材质和镜头表现，没有指定衣服时可结合情境设计；命名服装、逐角色删改、稳定外貌与可见性仍优先。仅有扶她设定不自动开启色气模式。

扶她规则只根据用户原始输入中的正向证据动态加入，参考图反推、搜索或引用补充中的性征不授予目标修改权限。NAI 将扶她实例计入全局 girls 人数，并只在对应角色框写 `girl, futanari`：单人全局 `1girl`，加一名女性 `2girls`，加一名男性 `1girl, 1boy`；其他同伴不因此改变性征。普通 Anima 的 `futa with female / futa with male` 不替代 NAI 人数；关系按原文解释，不因扶她设定自行判为 `hetero`。

NAI 的 `sexual_trait_authority` 与普通模式同样记录允许标志和被移除的内容。中文和英文未经正向要求的扶她、男性生殖器断言都受该权限约束；色气模式不开放额外性征。中文原文仍可以保留。两条路径都要求完整、协调的画面、准确主体和动作、连贯自然语言、不为固定 tag 数量补词；`-r` 保持自己的 JSON、逐实例位置和方向标签格式。

### 只表达画面中可见的外貌（2026-10-13）

普通写作（含自定义模板及改图）、NAI `-r`、旧多人 planner 和低 CFG constraint planner 共用可见性指引。先遵从用户指定的构图，未指定部分由模型选择；逐实例判断哪些身体部位在画内，再根据视角、姿势、衣物、遮挡和反射，只描写实际可见的外貌特征。身体部位入镜不代表其全部特征都可见，仍应保留可见的形态与细节。稳定档案提供事实，不是必须补齐的清单，也不能为展示档案而改变构图。

宿主保留已写出的正确事实，纠正已写出维度的档案冲突，不再填充未表达的维度或未提及的标志性特征。NAI 各实例独立选择，旧多人固定角色只使用 planner 选取的身份锚点，不因锚点为空复制整份固定外貌。低 CFG 规划还收到最终角色描述作为可见性上下文。模型若自行误写了不可见特征，仍需结合其原始输出排查；程序没有通用遮挡理解器。显式 omit、修改权限、raw 和 `#` 的既有边界保留。

用户明确要求角色某项外观不可见时，第一次 LLM 可把该角色的 `appearance_changes` 标为 `omit`。例如“爱音不画眼睛”会禁止爱音档案中的灰眼在后续提示词和 NAI `-r` 角色框中复活；同画面其他角色的瞳色不受影响。眼神、闭眼和高光变化仍保留瞳色，不能误当成不画眼睛。可在最近任务摘要的 `appearance_omissions` 中核对。

自然语言优化不是让两个 LLM 都自由写一遍：

1. 第一次 LLM 只理解请求，识别可见角色和每个人的服装选择。
2. 角色视觉档案提供 canonical 角色、稳定外貌和 default/casual/stage 等候选衣柜；衣柜只是候选资料，稳定外貌则是未被用户显式修改维度的基线。
3. 程序用统一的 `WardrobeAuthority` 决定哪些衣服本次有效，哪些历史衣柜已经失效。
4. 第二次 LLM 同时看到完整原文、逐角色稳定外貌和服装权限，并编写 Identity、动作、构图、背景和服装表达。`outfit_source` / cosplay 使用来源档案帮助理解，但数据库组件不会被主机自动追加到最终 `Details` 或共享 Tags；模型按用户原文选择需要的可见组件，后处理只阻止被删除、陈旧或属于其他穿着者的内容复活。
   原文明确写出“A cosplay B / 正在 Cos B 的 A / A 扮成 B / A 穿 B 的 cosplay 服装（或 cosplay 服）”，且 B 已解析为角色来源时，主机会额外加入 B 的 `_(cosplay)` tag（最终显示为 `b \(cosplay\)`）。NAI `-r` 会把它放进 A 的角色框，不留在全局提示词中。普通“A 穿 B 的衣服”、否定 cosplay、来源未确认或只是命名服装套组时不加；raw、`#` 尾缀和独立 `/anm 多人` 兼容模式不走这条规则。
5. 程序最后再次过滤第二次 LLM 的 Tags、Details 和 Nltags，并逐角色重建 Identity：LLM1 以可定位的 `appearance_changes` 提醒 LLM2 理解用户的外貌修改，稳定外貌档案仍是基线。主机不再用正则从用户原文猜测外貌维度；角色 `Details` 和共享 `Tags` 不能绕过这套外貌权限。

角色自有的 default/casual/summer/winter/stage 变体使用“穿着者 + qualifier”选择。用户可自然写“千早爱音穿着演出服”，无需重复成“千早爱音穿着千早爱音演出服”。普通衣物原文也会保留成显式 clothing anchor，因此不会因没有命名套组 tag 而被当成“衣服未指定”。

七字段外壳和有效人数锚点仍是硬格式要求。`Characters` 只是命名角色 roster：匿名、裁切或被景深遮蔽的人物仍由 `Count` 计数，不会因为没有 canonical 角色名而把合法回复判为无效。Identity/Details 内部则按自然语言宽松归属：角色名可出现在照片分镜等句子中而不必机械位于段首，后续无角色名的分号句继承上一明确角色，无法可靠归属的补充文字转入 `Nltags` 原样保留。模板仍要求每个命名角色段以 canonical 名开头，这是降低多人歧义的写作约定，不再是会截断内容或判整份回复无效的解析条件。

例如：

```text
/anm 百合婚礼、双女主、千早爱音、丰川祥子、白色婚纱、头纱、长手套
```

两人的粉/蓝发等稳定外貌继续来自角色档案，但两人的 default 校服不会生效。即使第二次 LLM 误写旧校服或其 jacket、shirt、skirt、necktie、socks 组件，程序也会按失效档案来源删除。

```text
/anm 爱音穿白色婚纱，祥子穿默认服装，在教堂合影
```

爱音的旧衣柜失效，祥子的 default 衣柜仍然有效。不同角色的衣服优先写入各自带角色名的 `Details`，而不是无归属的共享 Tags；`Nltags` 只保留未被 Identity/Details 表达的关系、方向和场景补充。

```text
/anm 千早爱音和丰川祥子在公园合影
```

衣柜缺省按角色判断，而不是按整条请求判断。某个角色没有自己的服装基础时，才读取 `unspecified_wardrobe_policy`；即使另一角色明确穿婚纱，也不妨碍该角色收到自己的 default 软参考。第二次 LLM 可根据完整场景决定沿用、改造或替换这份参考。若该角色已经明确穿连体泳装、白色卫衣、命名校服、常服或 cosplay，则不再读取 default。开发者级字段和完整优先级见 [角色与服装配置工作流](角色与服装配置工作流.md)。

如果用户明确提到了服装、套组或 cosplay 来源，但第一次 LLM 没有把证据可靠绑定到某个目标，状态会成为 `explicit_but_unresolved`。程序不会按标点或名称猜绑定，也不会恢复角色默认衣柜；第二次 LLM 根据完整原文和未绑定证据完成最终解释。真正没有服装基础的角色是 `unspecified`；只有增删、换色等修改而没有基础服装时也属于这种情况，但会加载 default 作为可修改的软参考，修改本身仍是硬要求。

## 命名服装套组与别名

经过本地校验的独立命名服装套组会作为 hard tag 保存。每个套组实体保存自己的变体和中英文触发别名，并指向一个 canonical Danbooru tag：

```text
haneoka_school_uniform
├─ 羽丘校服
└─ haneoka school uniform
```

用户输入任一别名时，最终提示词只注入一次 `haneoka_school_uniform`。下划线 canonical tag 不会再作为一条别名重复保存；它本身仍可直接匹配。不同套组实体允许指向同一个 canonical tag，不会仅按 tag 强制合并；匹配时仍保留各自别名、变体和角色绑定 anchor，最终 hard tag 再统一去重。

命名套组命中后被视为完整服装 anchor。LLM 可以遵循用户明确提出的颜色、增删衣物等修改，但不能自行编造并追加未经验证的套组组成。用户没有要求修改时，应保留 canonical 套组而不展开猜测其中的上衣、裙子或配饰。

命名套组与角色自己的多套衣柜是两类数据。`haneoka_school_uniform` 这类 Danbooru 服装词条及其冬夏组件属于通用套组，可以绑定给高松灯、爱音或任意其他穿着者；`chihaya_anon + stage` 这类“角色本人的演出服”才按角色 profile 选择。通用套组组件保存在套组自己的 `component_tags` 中，不会再伪装成角色视觉档案，也不会因目标角色不同而进入 stale 缓存。

## 默认自由创作

LLM 按主题补充角色服装、姿态与构图。普通优化和 NAI `-r` 没有背景需求时默认只用 `simple background, white background`，不自由设计地点、天气或光影；毕业、野餐等主题或动作若隐含需要配套环境，由模型结合完整原文补足场景，避免错误强制白底。用户明确简单白底优先。主机不根据地点关键词或背景标记补白底、删除模型场景；标记只作诊断。模板不要求固定 Tag 数量，普通七字段与当前 Nltags 处理保持。旧 `/anm 多人` 与 Turbo 兼容路径另按其现有策略执行。

角色身份、人数、用户明确指定的主体、关键服装、动作、表情和道具仍然是核心约束。自然语言生图不再使用普通模式的场景门控，也不再提供单次开启自由发挥的参数。

```text
/anm 一个女孩，白色裙子，立绘，简单背景
```

插件会把聊天模型生成的具体内容 tags，与质量词、固定角色、画风词等配置拼接后发送给 ComfyUI。

程序不要求 LLM 凑齐固定数量。合法七段输出的 `Tags` 不再套用旧的 65 个内容 tags 上限；旧平铺/非结构化回退仍保留该技术上限。质量词、固定角色、画师组和画风不计入旧回退的上限。

扶她与男性生殖器特征采用请求级来源门控。普通任务书和 system prompt 不常驻展示扶她计数示例；只有用户原文正向明确要求扶她时，才动态加入对应的 Anima `Count` 语义。自慰、色情场景、体位、服装或胸部尺寸都不是扶她或阴茎的证据；“不是扶她”“不要出现扶她”等否定表达也不会开启权限。即使第二阶段模型自行写出 `futanari / futa with ... / penis / erection`，程序仍会在结构化组装前移除没有正向用户证据的内容。`#` 后手工尾缀继续按原样保留。

模板会优先保留用户明确指定的主体、花卉、道具、动作、表情和镜头，并限制互相冲突的动作与神态。抽象主题至少保留两个直接可见的主题锚点，避免被常见礼服、花朵或场景素材取代。

合法七段提示词只经过精确去重、保留字段边界、质量词/画师词剥离，以及用户明确修改和已知陈旧衣柜的确定性冲突删除；不会再用衣物或外貌子串猜测并删除动作、配饰、镜头、场景或整句 Nltags。旧平铺回退仍保留原有较强清洗。千代turbo 的低 CFG Harness 保持原有的约束计划、优先 Tag、冲突删除、画风加权和动态截断。

## 多角色描述（推荐普通 `/anm`）

现在多个角色也推荐直接写 `/anm <多个角色的描述>`，走普通结构化 prompt 路径并按角色绑定身份、外貌和服装。例如：

```text
/anm 丰川祥子穿默认服装坐在左边，千早爱音穿羽丘冬季校服站在右边，若叶睦穿黑色葬礼服装站在两人身后
```

`/anm 多人 <描述>` 仍保留为不常用的兼容入口，用于旧的 2–4 人专用规划、多人候选和强制视觉检查流程。

兼容入口是独立路线，会在普通语义 LLM1 之前分流。它不读取普通路径的角色视觉档案或逐角色衣柜权限，也不借用普通 LLM1 的角色名/wardrobe 图；人物外貌与服装来自专用多人 planner 的 Character A/B/C/D 特征块、固定角色辅助信息和逐人 Danbooru 候选校正。

以下示例和专用构图、候选、自检说明只适用于这个兼容入口：

```text
/anm 多人 左边若叶睦抱着吉他，右边千早爱音牵着她的手
```

也可以使用半结构化描述：

```text
/anm 多人
左边：若叶睦，抱着吉他，安静
右边：千早爱音，粉色外套，开心地和她说话
关系：两人并肩走在放学路上
场景：秋日下午的街道
```

未指定尺寸时，多人模式会从可用尺寸中选择接近 3:2 的横图；用户明确写出的尺寸或“竖图/宽屏”等尺寸词始终优先。

固定角色辅助信息可为兼容入口提供权威外貌块；其他现有作品角色会按多人 planner 的候选逐人执行 Danbooru / Safebooru 校正。角色视觉档案与普通结构化路径的逐维度外貌合并不参与此入口。

多人规划只接受 left、right、center、foreground、background 等连续场景位置，并把互动收束为一条有方向的主关系。互动中的人物名会统一改写为 `Character A/B/C/D`，避免中文名、罗马字和别名被模型理解成额外人物。扑倒、拥抱、亲吻、扭打等身体重叠动作会组成一个共享接触组，不再同时要求左右分区。

正面提示词只使用“单一全画幅构图、同一镜头、同一时刻”等肯定式描述，不写入分屏、漫画格、重复角色等禁止概念；这些概念只保留在 `/anm 多人` 专用负面词中。LLM 返回的自由构图句不会直接进入最终提示词，插件会生成确定性的安全构图句。公共人数、场景、镜头和光影继续经过 Tag 清洗；每个人物的自然语言块、互动关系和空间关系不会送入 Tag 清洗器。

Turbo 模式仍对公共 Tag 应用低 CFG Harness，不会截断人物身份和互动句。多人任务会强制进行一次图片校验，额外检查人数、重复角色、分屏、身份串色和互动方向，并按现有重试上限尝试修正；普通 `/anm` 仍由全局图片校验开关控制。

第一版不提供每角色独立 LoRA、区域遮罩或 Regional Prompting。角色相似、三人以上或肢体交叠复杂时仍可能需要多生成几个种子筛选。

## 现成 tags

普通 `/anm` 会把现成 Tag 串也交给 LLM 重新设计。需要完全保留现成 tags 时，请使用 `/anm 无优化`。

Tag 串中可以包含一个已保存的中文固定角色名，例如：

```text
/anm 1girl, solo, 狐莉, knee up, standing on one leg, holding sword, point a sword at audience, serious
```

`/anm 无优化` 会跳过 LLM 优化，直接把用户提供的 tags 发送到工作流。

## 原样 tags 模式

如果你已经写好了完整 tags，可以使用：

```text
/anm 无优化 masterpiece, best quality, 1girl, solo, white dress, simple background
```

这种模式不会调用提示词优化模型。

与自动 tags 模式不同，`无优化` 会完全按原样使用后面的提示词，不再拼接质量词、固定角色、画师组或画风，也不执行内容 Tag 清理。

## 固定角色

在 `fixed_characters` 中添加角色：

```text
狐莉=1 girl, solo, fox girl, white hair, heterochromia, fang, black choker
```

之后在指令中明确提到角色名时，普通结构化路径会把这些内容作为角色身份辅助信息，并用于匹配结构化角色；`/anm 多人` 兼容路径和旧平铺回退路径会更强地注入这些内容。它们不应包含服装、动作、背景、质量词或画师词。

没有提到固定角色名时，插件不会自动套用角色。

固定角色、角色别名、视觉档案、服装套组和名词翻译的完整职责与注入顺序见 [角色与服装配置工作流](角色与服装配置工作流.md)。

## 画师与画风 tags

启用画师组后，插件会先拼接当前画师组 tags；当前启用的画风组会继续拼接在画师组之后，用于填写媒介、上色和渲染 tags。画风组通过 `style_presets` 保存，并用 `active_style_preset` 切换。

`default_artist_tags` 仅在没有启用画师组时作为备用画师 tags 使用。

聊天中的“创建/追加/切换画师组”只改变当前群聊或私聊会话启用的画师组；画师组名称和 tags 仍由所有会话共用。会话选择保存在插件数据目录的 `artist_sessions.json`，重载后继续生效。未单独切换的会话使用配置页的 `active_artist_preset`；切回“默认”会为该会话明确选择 `default_artist_tags`。`/anm 查看画师组` 的“当前”标记按所在会话显示。删除画师组后，使用它的会话切回默认画师 tags。`-sN` 仍只覆盖本次生成，不修改会话选择；原样/无优化路径仍不拼接画师词。

如果某次不想使用画师 tags，可以在指令里写：

```text
不使用默认画风
```

或：

```text
no artist tags
```

## 千代预设

在“千代预设”中选择“千代base”“千代aesthetic”或“千代turbo”后，会应用：

- 把对应的千代画师组写入画师 tags。
- 把狐莉写入固定角色。
- 千代base 使用 `anima_baseV10` 与 CFG 5，并保留当前正负面词。
- 千代aesthetic 使用 `anima_aestheticV11` 与 CFG 3，不注入固定正负面词。
- 千代turbo 使用带 `anima-turbo-lora-v0.2` 的自定义工作流、10 步、CFG 1、`euler/simple`，保留当前正负面词，并启用低 CFG 提示词约束。

狐莉只是可选固定角色，不会默认套用。选择“未启用”后，会重新使用预设启用前的基础配置。

## 图片参考

引用或直接发送图片后，可以使用：

```text
/anm 解析法术
/anm 反推这张图的提示词
```

也可以在生图请求里写“参考这张图”“图中衣服”“同款衣服”等，让插件把图片内容作为参考。
