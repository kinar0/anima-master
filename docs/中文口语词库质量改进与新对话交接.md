## 2. 为什么改变方向

原导入器保证了格式、去重、人工优先、容量和可恢复性，未保证别名自然、等价或适合用户口语。下列是实际新增词条的质量例子，不是推荐映射：

| canonical tag | 原导入别名示例 | 问题 |
| --- | --- | --- |
| `hug` | 抱拥 | 常见“抱抱”“拥抱”表达未被这组新增别名覆盖 |
| `headpat` | 头顶爱抚、拍头 | 表达生硬，“拍头”可能表示不同力度与动作 |
| `white_dress` | 白色裙装 | 日常“白裙子”也可能指半身裙，不能为提高命中而强绑连衣裙 |
| `spread_legs` | l字开脚 | 不符合一般中文口语 |
| `large_breasts` | 圧倒的胸囲、豊乳、着衣巨乳 | 日语混写；部分别名还包含 canonical tag 没有编码的附加条件 |

新增条目中 539 个别名含假名；纯汉字日语未计入。没有对全库做完整语义质量统计，不能把抽查扩大成“所有词条都错”或“只有日语词有问题”。同样，原有 1427 条也不自动视为全部优质。

Toolbox 还有模型组织查询、模糊搜索、分类浏览和手册加载；本插件当前使用本地字面匹配。只搬别名没有搬检索能力。多轮上限不能证明数据库质量是所有调用轮数的原因，不移植十轮工具循环。

目标改为：**让常见中文表达得到少量准确、有增益的 tag 参考，保留不确定时不命中的能力。** 条目总数、每词别名数和标签热度都不是质量结论。

## 3. 必须保持的边界

1. 多个等价中文别名可以指向一个 canonical tag；现有 `alias=tag` 格式已支持，不必先改 schema 或建第二个运行词库。
2. 一个中文表达有多种合理解释时，首版不强选一个 tag，也不新增多候选协议。保留原文给 LLM 判断；将歧义登记为“主动跳过”，不是自动修复缺口。
3. 保留大小、颜色、部位、姿态、对象与动作区别。例如不能把“裙子”统一当连衣裙，不能把“张开”不带部位就解释成腿张开。修辞、情绪或隐喻不能因字面重叠就触发具体视觉标签。
4. 映射候选始终只是参考。匹配到动作不证明动作属于哪个人，也不证明否定、背景提及或修改中的属性实际可见。
5. 新词不能覆盖现有人工映射。发现旧条目可疑时列入问题报告，不直接替用户删改。所谓“现有”只是权威优先，不能当作语义正确的评估金标准。
6. 默认本地处理，不在生图链加模型调用，不启动全库翻译/复核任务，不启用现有批量翻译命令来追求规模。离线付费模型生成候选也是单独选择，不是本计划的必需前提。
7. 不按假名或字符类型一刀切判定可用性：自动识别只负责标记；面向中文输入的候选需逐项审查语义和实际用法。保留现有人工日语/圈内表达，除非用户要求更改。
8. 复用 Toolbox 的词条、代码或材料时，保留 `third_party/llm_nai_toolbox/` 中的来源及许可说明，不虚构版权信息。

## 4. 执行顺序

### 阶段 1：读取基线并建立评估集

按 AGENTS.md 先完整阅读 README、中文提示词流程、角色与服装工作流、视觉档案优先级、prompting、troubleshooting；涉及配置再读 configuration。核对完整请求链、旁路、当前词库与本轮保留的代码修改。只做文档/数据工作时不凭记忆推断运行状态；修改生图相关代码前必须完成规定阅读。

只导出名词映射，不复制完整配置或 API key。将现有词条、候选别名、评估样本分开，防止候选评估反过来覆盖用户配置。

建议先建约 120–160 条中文请求的小型评估集，数量是工作量预算，不是凑数指标：

- 动作、表情、姿态、服装、道具和场景的常见说法与简短变体。
- 否定、比喻、含混短词、长短重叠、别人的属性、场景中提及的衣物等反例。
- 同一概念的不同语序、未列入候选别名的说法与确实需要上下文判断的例子。

已有用户提供的实际失败请求优先；没有足够真实样本时可先制作合成样本，但必须标注来源，不能宣称其代表真实使用分布。不要自动读取聊天记录或把真实记录提交外部服务。将约四分之一样本留作验收集，避免为同一组句子反复添别名、再用它们证明效果。

每个样本记录：原文、来源类型、适合提供的候选概念、禁止提供的误导概念、可接受的不命中、语义依据。预期不是最终提示词必含的 tag 清单，也不是按名字硬编码的规则。

先跑原有词库基线，分别统计正确参考、错误参考、漏匹配和主动跳过歧义。不把“命中了任意字符串”计为成功，不把候选未被 LLM 采用计为宿主错误。

### 阶段 2：制作小规模口语候选

从评估暴露的缺口出发，先选约 50–100 个有价值的概念；不足这个数量也可交付，不因预算而加入低质量项。先覆盖容易误译、用户反复使用的概念，不机械翻译整个英文词表。

候选 canonical tag 优先从当前本地 Anima/Danbooru 目录核对；Toolbox 仅为候选来源，不是正确答案。Anima 本地目录缺失不代表 NAI 一定不支持，应标注覆盖情况而非编造后端能力。不要为验证每个常用词逐个联网，也不要以语法有效冒充语义验证。

每个概念按实际用法给多个等价口语别名，不设“只能两个”的限制，也不要求机械凑够多个。保留自然短语，拒绝整段请求、随意添加主语或把否定句作为正向触发词。单纯穷举“一个/这位/正在”等组合不能替代匹配质量。

候选记录至少包含：canonical tag、中文别名数组、简短中文释义、来源、已有映射冲突、适用后端覆盖说明、正例、邻近反例、审查结论。运行配置仍只有经过验收的 `alias=tag`；释义和反例留在维护文件里，不默认增加 LLM 上下文。

现有 `noun_translation_batch.py` 的初译任务书和解析器最多允许 2 个别名，并带独立模型审核流程，不能直接拿它当本阶段执行方案。当前阶段可以用本地候选文件维护任意合理数量的别名，再展开成现有映射行；只有实际需要调整该批量入口时才改其协议及测试。先检查现有未跟踪文件，避免覆盖用户已有实现。

### 阶段 3：对比评估，必要时再改匹配

比较相同评估集上的“原有词库”和“原有词库 + 候选”，输出新增正确命中、仍缺失、新增错误命中与冲突跳过。对原有缺陷单独归因，避免把保留的旧问题算成新候选成功。

如果缺口来自匹配规则而非词条，先定位一般不变量，再决定是否修改。例如语序变化、否定范围或词边界应通过机制处理；不要靠添加完整失败原句补洞。任何规则变更都应保留最长重叠、独立位置命中、更新后缓存失效，以及附近不应匹配的反例。

不默认添加模糊匹配、编辑距离、去掉全部语气词或用包含关系猜词义；这些可能放大误匹配。只有基线显示真实收益、反例验证有边界时再独立提案。首批候选足以改善覆盖时，不为规划完整性重构 resolver。

对常见但模型本来就懂的表达，增加映射未必带来输出增益。没有真实模型对比时，只报告本地参考覆盖；不要推断提示词更准确或图片更好。是否进行真实模型/生图验证依下一任务授权、可用运行环境和成本约束处理，不让离线测试暗中触发收费调用。

### 阶段 4：发布合格小批次并记录

此阶段在用户授权实施词库更新的范围内执行；只要求规划或准备候选时停在可审查结果，不写运行配置。明确授权实施后可按以下规则完成，不重复申请同一授权。

复用既有配置/页面持久化入口，人工映射优先，应用前检查配置是否变化，原子保存，保存词库级快照和实际新增清单。不要将候选数据喂给全量 Toolbox 导入器后误导入 general 全库。不得复用或覆盖 `toolbox_import/applied.json` 的历史恢复清单。

重复合并不新增重复词；恢复只移除仍等于该批次导入值的新增词，保留用户后改内容及其他配置。记录磁盘、页面和运行时的同步状态。直接改磁盘配置时需重载插件并刷新页面，不能假装热更新。

首批验证有效后按真实缺口扩充下一批。记录需要上下文解释的歧义，不为覆盖率强绑它们。无需承诺最终扩展至多少万条。

## 5. 完成标准与停止条件

| 检查 | 本阶段交付标准 |
| --- | --- |
| 语义 | 每条新增别名有等价依据；有争议的别名跳过并解释 |
| 反例 | 验收集中由新候选造成的明确错误参考为 0；出现错误先修订或撤回相关候选 |
| 覆盖 | 报告实际新增正确参考及剩余缺口，至少在未用于添词的样本上验证；不预设虚假的提升百分比 |
| 不变量 | 候选不变 hard tag，不决定穿着者，不自动补回；普通/Nltags/背景/-r 已确认契约保持 |
| 数据 | 人工原值不覆盖，重复合并幂等，撤回保留后续用户编辑，无无关配置变化 |
| 性能 | 在实际批次规模和同一批短请求上对比匹配成本，有异常再排查；不以单次最好结果保证性能 |
| 证据 | 保存评估集、候选审查记录、基线与差异报告；发布时另保存批次清单 |

“反例 0 错误”仅针对该有限验收集，不是对所有中文输入的保证。若候选只是增加数目、在验收集没有新增正确参考，停止扩容并报告原因。若收益必须依赖上下文消歧，优先保留 LLM 原文判断，不顺势改成多轮工具系统。

只为实际改动运行相关测试：词条纯数据变更以语义审查和匹配评估为主；改 resolver 加有区分力的正反回归；改页面/导入才验证分页、全量保存和恢复。不要每次机械重跑历史 488 项或增加仅复制实现的断言。pytest 使用 AGENTS.md 的 bundled Python、core PYTHONPATH 和 `-p no:cacheprovider`。

## 6. 预期产物与新对话的起点

优先交付离线评估与候选文件，可采用 `vocabulary_quality/` 下的 `evaluation.jsonl`、`candidates.json`、`baseline.json`、`comparison.md`；文件名可按现有结构调整，**这些文件当前尚未创建**。大文件不用塞进提示词或配置，记录只涉及词汇，不含密钥。

下一对话建议以阶段 1–2 为第一项任务，接着依据结果完成阶段 3。先把候选质量与收益做成可审查结果，再根据用户是否授权应用执行阶段 4。其他已完成代码的真实模型验证作为单独剩余项，不混入词库扩容来宣称一并验收。
