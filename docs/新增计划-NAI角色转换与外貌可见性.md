## 2. NAI 转换链已有什么

已核对 `agent_tools/comfyui_workflows.py`：自定义工作流写入正负面文本后，在收到 `nai_characters` 时调用 `_apply_nai_character_prompts`。它为每个有效角色分配独立节点，实际连线为：

```text
characters[i].prompt（包括已接受的方向动作 tag）
  → ComfyUIToNovelAIV4.inputs.comfyui_prompt
  → 转换节点输出 0
  → CharacterPromptSelect.inputs.characterN
  → NovelAIGenerator.inputs.characterPrompts
```

“Convert ComfyUI to Novel AI V4”“NAI Character Prompt Select”是用户描述的界面名称；仓库 API JSON 的 `class_type` 分别为 `ComfyUIToNovelAIV4`、`CharacterPromptSelect`。不能直接用界面文字替换 API 类名。当前支持的实际节点类型还需按用户安装扩展核对，不凭名称相似改写。

角色坐标、开关与空负面角色输入由 selector 保存；未启用的占位角色是空字符串，无需创建无用转换节点。全局/负向输入通过 `_nai_prompt_slot` 跟踪既有 Textbox/转换链，不应绕过已有转换器，也不应将角色转换后再送进全局转换器。

`tests/test_nai_workflow.py` 已有同身份多格、方向动作、坐标和 V5 22 实例的工作流图检查；其中会沿角色连线读取 `comfyui_prompt`。这证明已有相关断言，但本轮未重跑，历史通过也不等于 ComfyUI 扩展实际执行成功。

## 4. 本轮发现的具体缺口

### 4.1 档案真实性与本次可见性混用

普通 `merge_authoritative_identity_block` 会追加未被 replace/omit、且模型尚未表达的稳定档案维度；`_build_nai_direct_prompt` 会过滤档案控制维度的原写法，再追加未被替换/省略的稳定 tags。两处都会使“模型有意不写画外瞳色”重新变成“有瞳色”。这是静态代码确认的补回通道，不是本轮真实模型复现结果。

因此，只在模板补一句“写可见外貌”可能无效。必须分别处理：

- **事实约束**：A 的瞳色若需要写，应来自 A 的有效档案或本次修改。
- **画面选择**：这次是否看得见 A 的虹膜、头发、耳朵、伤痕等，由最终视角、裁切和遮挡决定；存档有某项事实不代表必须输出。

不应为删眼睛而清空整份档案或永久修改 profile，也不能把“不在画面中”当成“换成其他值”。

### 4.2 各入口的覆盖不同

普通模板已有“可见元素”措辞，但 Identity 样例和完整稳定外貌上下文容易被当成必须照抄。NAI 任务书明确逐实例作用域，却没有充分说明稳定外貌也需按该实例的可见部分选取。

旧 `/anm 多人` planner 要求 `identity_anchors` 是可见特征，但固定角色的 `appearance` 留空；`render_character_block` 在没有选出 anchors 时仍可能整串加入 `fixed_tags`。普通非结构化兼容回退也存在稳定外貌进入 required tags 的通道。两者都不能因普通 writer 已更新就自动算完成。

Turbo/low-CFG 后续 constraint planner 还能生成 priority tags；其权限差异已有延后记录，需要审计是否重新引入隐藏特征，不能顺带重写整套衣柜或 Harness。

### 4.3 既有“闭眼”边界需明确

当前显式 omit 规则刻意不把“闭眼、眼神无光、没有高光”归为眼睛缺席，防止误删眼部表现。新增可见性要求不能直接把这三者统统改成 omit。

完全闭眼可能看不到虹膜颜色，但闭眼形态仍需保留；眼神无光或没有高光时虹膜仍可能可见。下一实现应区分眼部形态/动作与虹膜颜色，必要时更新“完全闭眼仍必须保留瞳色”一类旧断言，并说明契约变更理由。不要只改测试让错误代码通过。

## 5. 修改方案设计记录（实际实施见第 8 节）

### 5.1 一份简短的共用模型指引

对实际参与画面提示词写作/补写的模型统一表达以下原则，按已有入口追加，不依赖用户自定义模板一定有某个占位符：

> 稳定角色档案描述角色本身，不是本图必须列出的清单。先根据本次最终构图、身体与头脸朝向、裁切、遮挡和反射判断每个可见实例实际能看见哪些部位，只写这些部位的外貌特征。正背面不同或同一角色跨格出现时分别处理。仅从背面且脸眼未露出的实例不要写瞳色；回头露眼、侧脸露眼或清晰镜面反射时按实际可见内容保留。不要为了展现档案特征改变用户姿态或镜头；可见特征仍遵循该角色档案和用户修改。

普通七字段及 Nltags 格式不变；规则同样约束 Identity、Details、Tags 与 Nltags，不把删除的外貌换成另一个字段中的完整自然语言复述。不常驻塞入大量例子，不增加生图中的模型调用轮数。

覆盖普通优化的 Anima/NAI、自定义工作流、NAI `-r`、旧多人，以及实际启用的 Turbo/low-CFG 补写。实验性图生图若复用普通 writer，应沿用规则并保留原图构图；不得因为模板更新而声称 NAI 图生图已支持。

raw/关闭优化没有写作模型，`#` 手工尾缀属于既有原样契约，不执行新的自动外貌删改。负向词和用户手工配置的质量/画师串不当成角色档案扫描清空。用户确实要求这些直通入口也自动清理时，另行确认契约变化。

自定义模板不整段覆盖；内置模板改变时同步 `_conf_schema.json` 默认文本与历史指纹迁移，保留真正的用户自定义值。必要指引应在公共构建入口追加，避免自定义模板漏占位符后失效。

### 5.2 宿主不能反向补回不可见特征

首选方向是：**writer 决定哪些外貌在该实例中需要表述；宿主继续纠正已表述特征的事实冲突，而不因档案维度缺失就无条件补齐。** 保留显式 omit 的硬删除和 replace/additive 的权限，避免把可见性改动误做成放弃身份约束。

实现前需对普通与 NAI 两处补回代码设计成对验证：模型只写可见的头发、不写画外眼睛，最终不追加瞳色；模型在可见眼睛的实例写错颜色，仍按该角色权限处理。可以删除冲突值或在该维度确实需要表达时恢复有效值，但不能为了恢复正确颜色而改变用户镜头。

复用已有镜头分类处理明确的画外范围，逐角色/逐实例应用。不能将一个角色的背向、闭眼或头部出框变成整图全员删除，更不能仅看 global 的一个 `from behind` 就删所有实例瞳色。

首版不先造庞大的中文遮挡关键词表，不靠单个姿势词推断全部人体可见性，不增加第三次 LLM“审核后重写”。没有可靠归属或语义证据时保留原文和模型判断，不猜一组维度去批量删除。

普通七字段先保持协议不变。若受限于现有数据无法表达必要的实例可见性，应在实施记录中提出具体缺口和最小方案，再决定是否需辅助元数据；不能先全面 JSON 化或强加新的固定长输出。本文件没有预先批准一套可见性枚举/schema。

### 5.3 固定角色、回退及低 CFG 的补回审计

固定角色继续提供真实身份和稳定事实；planner 必须按可见内容选 anchors。没有 anchors 不应成为自动照抄全串外貌的理由，但 canonical 身份也不能因无可见眼睛而丢失。旧回退通道单独报告边界，不从字段名猜测其行为。

低 CFG planner 明确不把不可见外貌重新加入 priority tags；已有约束仍以该实例的可见表达为基础。若代码会在 writer 后自动恢复，须定位到具体消费点再改，不用一个全局清洗器把所有角色外貌或优先 tag 删除。

## 6. 回归与反例清单

以下是语义验收场景，不是要写入程序的角色名或原句特例。用至少两种角色/档案和多种表达覆盖一般规则。

| 场景 | 应有结果 | 防止的误修复 |
| --- | --- | --- |
| A 仅背面，脸和眼睛不可见 | 保留身份、可见头发/耳朵等；不补瞳色和正脸特征 | 不能清空 A 全部外貌 |
| A 背向但回头露出一只眼睛 | 保留可见眼部特征 | 不能 `from behind → 无眼睛` |
| A 背面，镜中清晰露脸 | 按镜中实际可见特征写眼睛 | 不能忽略反射 |
| A 的虹膜完全遮住，B 正面露眼 | A 不写瞳色，B 保留自身瞳色 | 不能请求级一刀切 |
| 同一角色左格背面、右格正面 | 各实例分别选择，右格档案值仍正确 | 不能按 canonical 名合并可见性 |
| 头部完全出框/只拍手脚 | 不补头发、瞳色和脸部特征 | 不把场景“背景中有人”当无人或丢身份 |
| 脸部近景、上半身或局部取景 | 保留画面内特征，省略明确画外特征 | 不重写已工作的衣柜裁剪 |
| 完全闭眼；无高光但睁眼 | 前者保留闭眼形态并评估虹膜不可见；后者仍可写瞳色 | 不把眼部表情等同于删除眼睛 |
| 戴帽但仍露出头发；透明/半遮挡物 | 保留实际露出部位 | 不见遮挡词就清空对应维度 |
| LLM2 自行选背向，原文没写 omit | 最终组装不追加被省略的画外外貌 | 不能只验证 LLM1 显式 omit |
| 可见眼睛，writer 写错档案颜色 | 原有事实权限继续纠错 | 不能以可见性为名放行错色 |
| 明确改色但眼睛画外 | 修改仍作为事实证据保存，本图不强迫出现 | 用户改色不是改镜头授权 |
| raw 或 `#` 明确写眼睛 tag | 沿用原样契约 | 不把新规则扩成未经要求的手工词清理 |

模型选择隐含可见性是否正确与宿主是否透传分别验收。受控输出能验证不补回/不串人，不能证明真实模型理解所有遮挡。付费模型/生图按后续授权和运行条件单独验证并报告；不要再以历史 488 项通过替代新契约测试。

优先检查 `tests/test_nai_workflow.py`、`tests/test_prompt_direct_writer.py`、`tests/test_prompt_strategy.py`、`tests/test_prompt_background.py`、`tests/test_multi_person_prompt.py`、`tests/test_prompt_constraints.py`；实际改了模板再测默认迁移，改了入口再测相关旁路。按 AGENTS.md 使用 bundled Python/core PYTHONPATH/无 cacheprovider，不机械重复全库测试。
