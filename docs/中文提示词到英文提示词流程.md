# 用户中文提示词 → 最终英文提示词：完整流程

> 本文档记录本插件从「用户输入中文提示词」到「最终生成英文提示词」的完整处理过程。

## 核心结论

本插件**没有独立的「中译英翻译模块」**。中文到英文 Danbooru 标签的转换，**由对话型 LLM 本身完成**：

- 系统提示词是**中文**写的，明确要求模型「只输出英文 Danbooru 风格标签」。
- 用户输入的中文提示词原样进入 LLM，LLM 输出英文标签。
- 本地存在一系列辅助组件（Danbooru 解析器、语义锚点、背景意图检测、约束规划等），用于在 LLM 输出前后做**校验、修正与补全**，但真正的语义转换仍依赖 LLM。

整条流水线可以概括为：

> 中文指令 → 命令路由 → 任务编排 → 预处理（raw/预设/固定角色/感性/服装迁移）→ 研究计划（联网/深度思考）→ 语义锚点解析 → **LLM 中文→英文标签生成（七花括号结构化协议）** → 后处理（结构化解析、角色解析、背景意图、约束规划）→ 最终英文提示词组装。

---

## 阶段 1：命令入口与路由

入口位于 [`main.py`](main.py:538)：

| 命令 | 别名 | 处理函数 |
|------|------|----------|
| `/anm generate` | 生图、画图 | [`cmd_generate()`](main.py:538) |
| `/anm multi_person` | 多人 | [`cmd_multi_person()`](main.py:547) |

两者最终都通过 [`_handle_action()`](main.py:488) 进入 [`CommandActionHandler.handle_action()`](command_actions.py:359)。

- **generate 动作**：解析尺寸后调用 [`self._generate(...)`](main.py:366)。
- **multi_person 动作**：在 [`handle_action()`](command_actions.py:359) 中根据中文关键词（牵手 / 拥抱 / 接吻 等）选择目标宽高比，并设置 `multi_person=True`。

随后 [`_generate()`](main.py:366) 调用 [`_build_anima_prompt()`](main.py:301)，后者再调用 [`self._prompt_pipeline.build(...)`](prompt_pipeline.py:1447) 得到最终提示词。

---

## 阶段 2：生成任务编排 [`generation_task.py`](generation_task.py:93)

[`GenerationTaskRunner.generate_payload()`](generation_task.py:93) 是每次生图的实际编排器，流程如下：

1. [`split_manual_prompt_suffix()`](generation_task.py:9)：按 `#` 后缀拆分出「手动补充咒语」，主提示词走优化，后缀稍后再拼回。
2. `_augment_reference_image`：若用户提到参考图，从引用图片提取/补充参考上下文（[`message_context.py`](message_context.py:169)）。
3. `_augment_quoted_spell`：若用户引用了一段「咒语」，则抽取引用内容并增强提示词（[`message_context.py`](message_context.py:130)）。
4. `_build_prompt(event, prompt, multi_person=..., original_user_prompt=...)` → 调用 [`PromptPipeline.build()`](prompt_pipeline.py:1447)。
5. [`insert_manual_prompt_suffix()`](generation_task.py:17)：把第 1 步拆出的后缀拼回最终提示词。

失败路径包括：模型拒绝、多人计划失败、提示词降级。

## 阶段 3：预处理 [`PromptPipeline.build()`](prompt_pipeline.py:1447)

这是核心入口，按顺序执行以下预处理：

1. **清洗提示词**：移除 `--自由发挥 / --创意拓展` 等传统标志，规范化分隔符。
2. **禁用优化短路**：若 `prompt_optimize_enabled` 关闭，直接返回原始提示词。
3. **raw 模式检测**：`strip_raw_prefix()`（[`prompt_presets.py`](prompt_presets.py:625)）识别「原样 / 直接画 / 不优化」等前缀，命中则绕过 LLM 优化。
4. **应用配置预设**：`apply_config_preset()`（[`prompt_presets.py`](prompt_presets.py:212)）。
5. **固定角色匹配**：`mentioned_fixed_characters()`（[`prompt_presets.py`](prompt_presets.py:603)）与 `selected_fixed_character()`（[`prompt_presets.py`](prompt_presets.py:595)）。
6. **感性模式检测**：`wants_sensual_mode()`（[`prompt_presets.py`](prompt_presets.py:650)）。
7. **关键词规则匹配**：`match_keyword_prompt_rules()`（[`prompt_keyword_rules.py`](prompt_keyword_rules.py)）。
8. **服装迁移检测**：`detect_outfit_transfer()` + `bind_explicit_outfit_patch_target()`（[`outfit_transfer.py`](outfit_transfer.py)）。
9. **获取 provider_id**：通过 `_current_chat_provider_id()` 选择实际执行 LLM 的 provider；无 provider 则回退。

---

## 阶段 4：研究计划与语义锚点解析

1. **研究计划**：[`PromptResearcher.plan()`](prompt_research.py:97) 检查用户中文提示词是否命中「联网 / 搜索 / 官方图」等 `WEB_SEARCH_KEYWORDS` 或「深度思考 / 严格还原」等 `DEEP_THINKING_KEYWORDS`；命中时可能执行 [`search_context()`](prompt_research.py:134)（使用 Tavily 联网搜索）。

2. **语义锚点解析**（中文 → Danbooru 候选）：
   - [`_generate_semantic_plan_with_llm()`](prompt_pipeline.py:693) 生成语义计划；
   - [`parse_semantic_plan()`](danbooru_semantic.py:211) 从中文用户提示词中提取 `source_text`；
   - [`resolve_semantic_anchors()`](danbooru_resolver.py:582) 调用本地 CLI（[`lookup_semantic_anchors()`](danbooru_semantic.py:358)）批量验证候选英文标签；
   - [`merge_semantic_results()`](danbooru_semantic.py:649) 合并缓存与本次查询证据。

这一步是用**本地 Danbooru 检索**对 LLM 后续输出做「锚点」支撑，本质上是一种语义对齐的预解析，而非完整翻译。

## 阶段 5：LLM 中文 → 英文标签生成（核心）

这一步发生在 [`_generate_prompt_tags_with_llm()`](prompt_pipeline.py:539)，是整个「中译英」的关键：

- 通过 [`build_llm_prompt()`](prompt_templates.py:81) 组装提示词，其底层模板是 [`DEFAULT_LLM_PROMPT_TEMPLATE`](prompt_templates.py)（模块级常量，中文撰写）。
- 模板明确要求模型**只输出英文 Danbooru 风格标签**，并采用**七花括号块结构化格式**：

```
{Count}  {Characters}  {Copyright}  {Identity}  {Details}  {Tags}  {Nltags}
```

  示例形如 `{{Count: 2girls, yuri}}` 等。
- `Count` 采用“一步查表”决策：`Count` 人数直接等于 `Characters` 项数，禁止反复核算。扶她计入女生人数：1 女 + 1 扶她 = `2girls, futa with female`，2 女 + 1 扶她 = `3girls, futa with female`，单独扶她 = `1girl, futanari`，1 男 + 1 扶她 = `futa with male`。禁止把 `futanari` 当作人数 tag 单独使用。
- 模板会格式化注入以下上下文块：`theme`、`search_context`（联网搜索结果）、`character_rule`（固定角色规则）、`outfit_transfer_rule`（服装迁移）、`reference_rule`（参考图）、`img2img_rule`、`sensual_rule`（感性），并追加 `build_keyword_rule_block` 与 `BACKGROUND_POLICY_TEMPLATE`。

**多人场景**走独立分支 [`_build_multi_person_prompt()`](prompt_pipeline.py:773)：

- 先 `build_multi_person_plan_prompt()` → `_generate_multi_person_plan_with_llm()` 得到结构化多人场景计划；
- 解析后对每个角色单独做 Danbooru 解析（[`resolve_detailed()`](danbooru_resolver.py:742)），再由 `render_multi_person_character()` 渲染，最后 `build_final_prompt()`。

**单人场景**顺序：

1. 构建服装摘要；
2. `build_llm_prompt()` → `_generate_prompt_tags_with_llm()`（中文提示词 → 英文标签）；
3. [`is_chinese_model_refusal()`](prompt_pipeline.py:212) 检测模型是否「中文拒绝」而非返回英文标签；
4. [`extract_structured_prompt()`](prompt_pipeline.py:265) 解析七花括号结构化响应；
5. 若响应非结构化，则用严格格式提示词重试；
6. 解析每个角色的身份/详情，并对角色核心标签做 [`resolve_detailed()`](danbooru_resolver.py:742) 解析；
7. [`extract_background_mode()`](prompt_background.py:147) + [`enforce_user_background_intent()`](prompt_background.py:134) 处理背景意图；
8. 可选 [`_generate_constraint_plan_with_llm()`](prompt_pipeline.py:709) 生成约束计划（低 CFG 工作流）。

---

## 阶段 6：后处理

1. **结构化解析与重试**：[`extract_structured_prompt()`](prompt_pipeline.py:265) 解析七块结构；非结构化则重试。
2. **角色核心标签解析**：[`resolve_detailed()`](danbooru_resolver.py:742) 与 [`required_core_tags_for_prompt()`](danbooru_resolver.py:544) 基于本地 Danbooru 证据修正角色标签。
3. **背景意图**：[`user_requests_explicit_background()`](prompt_background.py:96) 通过中文场景标记词 / 英文场景正则判断用户是否显式要求背景，再经 [`enforce_user_background_intent()`](prompt_background.py:134) 落实。
4. **约束规划**（可选）：[`build_constraint_plan_prompt()`](prompt_constraints.py:34) 生成英文 JSON 规划 → [`parse_constraint_plan()`](prompt_constraints.py:89) 解析 → [`apply_prompt_constraints()`](prompt_constraints.py:129) 应用加权样式标签 / 优先级标签 / 移除。
5. **标签清洗**：[`clean_content_tags()`](tag_cleaner.py:314) 负责去重、质量词屏蔽名单过滤、角色身份剥离、多角色屏蔽、排除组处理；[`split_tags()`](tag_cleaner.py:190) 与 [`join_prompt_parts()`](tag_cleaner.py:404) 处理切分与拼接。

---

## 阶段 7：最终英文提示词组装 [`build_final_prompt()`](prompt_builder.py:64)

最终由 [`build_final_prompt()`](prompt_builder.py:64) 按以下结构拼装英文提示词：

```
quality 前缀
+ count / core / 角色 / style 标签
+ 清洗后的 content 标签
+ narrative 块
+ Nltags
```

存在 `preserve_structured_order` 分支时，保持七花括号块原始顺序。

## LLM 调用次数说明（重点）

**中文 → 英文的语义转换主要靠 LLM，且默认路径固定调用两次 LLM**：

### 第一次：语义锚点规划 LLM —— [`_generate_semantic_plan_with_llm()`](prompt_pipeline.py:693)

- 调用位置：[`build()`](prompt_pipeline.py:1603) 第 1603 行。
- 触发条件：`semantic_lookup_available()` 为真，即 `danbooru_semantic_lookup_enabled`（默认 `True`，见 [`danbooru_resolver.py`](danbooru_resolver.py:575)）**且**本地 Danbooru CLI 路径可解析（[`resolve_local_cli_path()`](danbooru_semantic.py:286)）。
- 作用：让 LLM 从**中文提示词**里提取「语义锚点」（中文 `source_text` → 候选英文 tag），再由本地 Danbooru 检索验证。它**不直接产出最终提示词**，而是先做一轮「中文 → 英文候选锚点」的语义规划。

### 第二次：主标签生成 LLM —— [`_generate_prompt_tags_with_llm()`](prompt_pipeline.py:539)

- 调用位置：[`build()`](prompt_pipeline.py:1926) 第 1926 行。
- 作用：这是真正的「中文 → 英文 Danbooru 标签」转换，输出七花括号结构化块。

> 只要本地 Danbooru CLI 已配置（默认开启语义查询），标准流程就固定会跑这两次 LLM。如果本地 CLI 不可用，则退化为只有第二次。

### 实际可能触发的额外 LLM（最多共 6 次）

| # | 方法 | 位置 | 触发条件 |
|---|------|------|----------|
| 3 | 结构化格式重试（再次 [`_generate_prompt_tags_with_llm()`](prompt_pipeline.py:539)） | [第 1991 行](prompt_pipeline.py:1991) | 第二次输出非结构化、且不含 `_(` 时，用严格格式提示词重试 |
| 4 | 服装摘要 LLM [`_generate_outfit_summary_with_llm()`](prompt_pipeline.py:593) | [第 1810 行](prompt_pipeline.py:1810) | 服装迁移启用 + 有联网搜索上下文 + 无既有服装摘要 |
| 5 | 角色候选提取 LLM [`_generate_character_candidates_with_llm()`](prompt_pipeline.py:621) | [第 2249 行](prompt_pipeline.py:2249) | 非结构化模式、非固定角色、角色核心标签未解析时 |
| 6 | 低 CFG 约束规划 LLM [`_generate_constraint_plan_with_llm()`](prompt_pipeline.py:709) | [第 2291 行](prompt_pipeline.py:2291) | `low_cfg_harness_enabled` 为真（千代预设默认 `True`，见 [`prompt_presets.py`](prompt_presets.py:115)） |

### 多人模式（额外一次前置 LLM）

[`_build_multi_person_prompt()`](prompt_pipeline.py:773) 在进入上述流程前，还会先调用 [`_generate_multi_person_plan_with_llm()`](prompt_pipeline.py:736) 生成结构化多人场景计划，再对每个角色走本地 Danbooru 解析（[`resolve_detailed()`](danbooru_resolver.py:742)，这一步是本地联网检索，不是 LLM）。

**结论：单次生图实际 LLM 调用次数在 1～6 次之间波动，而「两次」是默认开启本地语义校验时最典型的核心调用次数。**

## 流程总览（文字版）

```
用户中文提示词
   │
   ├─ main.py: cmd_generate / cmd_multi_person（命令入口）
   │
   ├─ command_actions.py: handle_action（分派、多人关键词→宽高比）
   │
   ├─ main.py: _generate → _build_anima_prompt
   │
   ├─ generation_task.py: generate_payload
   │      ├─ split_manual_prompt_suffix（# 后缀拆分）
   │      ├─ message_context.py（参考图 / 引用咒语增强）
   │      └─ prompt_pipeline.py: PromptPipeline.build
   │            ├─ 清洗 / raw / 预设 / 固定角色 / 感性 / 关键词规则
   │            ├─ outfit_transfer.py（服装迁移）
   │            ├─ prompt_research.py: plan / search_context（联网/深度思考）
   │            ├─ danbooru_semantic + danbooru_resolver（语义锚点解析）
   │            ├─ 多人 → _build_multi_person_prompt（逐角色规划与解析）
   │            │   单人 → prompt_templates.build_llm_prompt
   │            │         → _generate_prompt_tags_with_llm（★中文→英文标签）
   │            │         → extract_structured_prompt（七块解析/重试）
   │            │         → resolve_detailed（角色核心标签修正）
   │            │         → prompt_background（背景意图）
   │            │         → prompt_constraints（可选约束规划）
   │            └─ prompt_builder.build_final_prompt（最终英文组合）
   │
   └─ generation_task.py: insert_manual_prompt_suffix（# 后缀拼回）
```

## 一句话总结

**中文语义主要由 LLM 通过中文系统提示词「翻译」为英文 Danbooru 标签（默认两次 LLM：一次语义锚点规划 + 一次主标签生成），本地 Danbooru 组件负责在前后两端做语义锚定与结果校验/清洗，最终由 [`build_final_prompt()`](prompt_builder.py:64) 组装成发送至 ComfyUI 的英文提示词。**
