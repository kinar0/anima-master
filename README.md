# Anima 绘图大师

> **提示词维护严正警告（包括用户本人）：不要随便精简或简化给 LLM 的提示词。** 文字长或看似重复不代表没有功能；“整理、精简、优化”默认必须保留全部职责、约束强度和工作流。修改前先读 [提示词维护要求](docs/prompting.md#严正警告不要随便精简或简化给-llm-的提示词)，不要再以功能退化换取表面简洁。

这是一个自用维护的 AstrBot 插件：在聊天中接收中文描述或 Danbooru tags，经 ComfyUI 的 Anima 工作流生成图片，再把结果发回聊天。它在原项目基础上加入了角色视觉档案、自由命名衣橱、逐角色服装权限、画师组和多种提示词模式。感谢原作者提供的 Danbooru skill。

当前版本为 `0.8.0+local`。插件主要面向已经能运行 AstrBot、ComfyUI 和 Anima 模型的用户；默认工作流是 `anima_t2i`。也可以配置自己的 ComfyUI API 工作流，包括通过 `ComfyUI_RS_NAI_API_Request` 调用 NovelAI 的工作流。

## 快速开始

1. 确认 AstrBot 可以访问 ComfyUI，且 ComfyUI 已安装所需的 Anima 模型、文本编码器和 VAE。
2. 在 AstrBot 插件配置页填写下列最小配置。模型名称要与 ComfyUI 下拉框中的文件名一致。

   ```text
   comfyui_base_url = http://127.0.0.1:8188
   workflow = anima_t2i
   unet_name = 你的 Anima 模型文件名
   clip_name = 你的文本编码器文件名
   vae_name = 你的 VAE 文件名
   ```

3. 在聊天中发送：

   ```text
   /anm 一个女孩，白色裙子，立绘，简单背景
   ```

`127.0.0.1` 指 **AstrBot 所在机器**。如果 ComfyUI 在另一台机器，请填写 AstrBot 能访问的局域网或 Tailscale 地址。通常先手动启动 ComfyUI 即可；只有启用 `auto_start` 时才需要配置 `startup_command`，该命令也在 AstrBot 所在机器执行。详见[安装与快速开始](docs/quickstart.md)和[部署拓扑](docs/deployment.md)。

## 聊天指令

| 用途 | 示例 | 说明 |
| --- | --- | --- |
| 自然语言生图 | `/anm 千早爱音穿白色婚纱站在花园里` | 默认入口；多人也直接写在同一描述中。 |
| 指定尺寸 | `/anm 1216x832 两人在河岸合影` | 也可写“竖图”“横图”，或在末尾加 `--尺寸 1216x832`。 |
| 原样 tags | `/anm 无优化 1girl, solo, white dress` | 跳过提示词优化，按所给 tags 生成。`原样`是同义命令。 |
| 手动追加 tags | `/anm 花园里的女孩#backlighting, looking at viewer` | 第一个 `#` 后的内容原样加入最终正面提示词，不参与语义分析。 |
| 本次选择画师组 | `/anm -s1 狐莉站在树下` | 仅影响本次生成，不改变当前会话的画师组。 |
| NAI 逐角色提示词 | `/anm -r 左格高松灯站立，右格高松灯坐下` | 需要 NAI API 工作流和提示词优化；为各可见角色实例生成独立提示词与位置。 |
| 图片信息 | `/anm 解析法术`、`/anm 反推` | 附图或引用图片后使用；前者读内嵌生成信息，后者用视觉模型反推。 |
| 检查运行状态 | `/anm 状态`、`/anm 诊断`、`/anm 调试状态` | 分别查看服务状态、部署连接和任务摘要。 |

`/anm` 也可写成 `/anima` 或 `/comfyui`；`/anm 帮助` 会显示聊天内的指令表。其他管理命令包括 `/anm 查看画师组`、`/anm 创建画师组 <名称>=<tags>`、`/anm 切换画师组 <名称>`、`/anm 删除画师组 <名称>` 和 `/anm 添加角色 <名称>=<tags>`。画师组内容由各会话共用，但聊天中选中的画师组按群聊或私聊会话分别保存。

管理员可用 `/anm term_preview` 查看离线名词翻译候选，再用 `/anm term_translate <DeepSeek provider ID>` 分批初译并自动复核。已有的初译可用 `/anm term_verify <DeepSeek provider ID>` 单独复核；`/anm term_import preview` 查看可导入数，确认后用 `/anm term_import apply` 批量导入现有名词词库。这些管理命令不会提交生图。
候选覆盖本地 Anima 标签库中帖子数至少 1000 的全部通用 tag，按热度降序排列，不再限于前 1000 个。已有翻译和复核断点继续使用，每次最多初译 50 个尚未处理的 tag。
同样的批量流程也可在 WebUI 插件详情页的“服装词库 → 批量名词翻译”操作：填写 provider ID，逐批翻译、查看复核结果和冲突，再点击导入。长时间模型调用会在后台继续，页面自动刷新进度；导入后的条目可在页面上方“名词翻译”列表中修改。
Toolbox 0.9.8 的全量通用词库导入已因别名质量不足撤回，名词翻译恢复原有词条。来源、MIT 与恢复记录见 [配置说明](docs/configuration.md#toolbox-词库导入与撤回记录)；后续按中文口语质量计划筛选小批候选，不自动重新全量导入。

名词翻译、角色衣柜、通用套组及批量断点预览默认每页 30 条，支持翻页、页码跳转和每页数量切换；搜索覆盖完整分类，跨页编辑会一起保存。名词翻译页面最多可保存 50000 条。
完整批量进度按需展开；另有“词汇候选与释义审核”，可查看 Toolbox 的选定别名、释义、易混概念及正反例，保存保留/采纳/修改/暂缓/拒绝决定。审核决定独立存储，采纳项仍需验收，不直接导入词库或调用模型；字面相近查找不参与生图匹配。
该面板的“名词翻译参与生图”开关可随时停用全部名词映射：关闭后普通优化与 NAI `-r` 都不再读取它们作为模型参考，已保存的词库与批量断点保留。重新开启即可恢复，默认开启。

明确填写数字尺寸时，宽、高均须在 512–1756 之间且为 4 的倍数，无须预先加入配置列表。非生图白名单用户本次指定的尺寸（包括比例快捷词）不得超过 1MP，按 1024×1024 像素计算；未指定尺寸时仍使用原有默认值。“竖图”“宽屏”等比例词则从 `allowed_sizes` 中选最接近的尺寸。NAI 工作流的单次尺寸还须是 64 的倍数。

## 提示词如何生成

NAI `-r` 的实际提示词使用英文视觉 tags 与中文自然语言并存的形式。中文要求针对完整描述句，不能把英文 tags 一起翻成中文关键词，也不能只留下英文身份名和方向标签；全局与各角色实例都分别保留相应的英文细节与中文描述。

外貌只表达本图实际可见的部分。角色档案仍约束已写出的发色、瞳色等事实，但程序不再补齐模型省略的全部档案特征；背面不露眼、头部出框等构图不会因存档有瞳色而强行补眼睛。回头、侧脸和镜中露脸由模型按实际可见情况判断，各角色与 `-r` 各实例独立处理。原样模式和 `#` 手工尾缀仍原样保留。

普通 `/anm` 先分析原文中有哪些角色、各自的服装与外貌修改，再匹配本地角色视觉档案、命名服装和可用的 Danbooru 证据。第二次模型调用会结合原文和这些证据写出七字段英文提示词；程序随后按角色过滤陈旧衣柜与冲突外貌，组装最终 tags 并提交 ComfyUI。Danbooru 查询不可用时仍会分析角色与服装关系，只跳过相应查询验证。

角色的稳定外貌与服装档案分开处理。明确指定的衣服、换色或删除要求优先于存档衣柜；一个角色换装不会让其他角色的默认衣服被错误选中。未指定服装的角色可以把默认档案作为软参考；明确写“默认服装”才会选择该档案。`常服`指作品中的官方 casual 造型，`私服`或`居家私服`则交给模型自由设计。普通优化和 NAI `-r` 在没有背景需求时默认简单白底；主题、活动或动作隐含需要环境时，由模型补足配套场景。主机不根据地点关键词或控制标记强制补白底、删除已设计场景。

可选的 `comic_dialogue_enabled` 默认关闭。开启后，文本生图请求中明确标记的漫画对白、内心独白、旁白，或带说话人的引号台词，会从原文复制并在发送前排字。短台词优先放入画面内的气泡；空间不足时使用图片上方的对白区。NAI 与 Anima 共用这一独立步骤，原图保持不变；没有可识别台词的请求沿用原流程。排字失败时不会发送缺台词的原图。详见[提示词与角色画风](docs/prompting.md#漫画台词原文排字)。

NAI 原生文字支持明确的写字/说话引号、`角色：“台词”`、按画格指定的对白/旁白，以及末尾的多行 `Text:`。优化请求会自动复用逐实例写作者，按“文字出现次数—画格—角色实例/旁白—位置”绑定：对白进入对应实例末尾的 `Text:`，旁白和无主物件文字保留带画格/位置说明的 base 尾段；同名角色跨格分别处理，不把全篇台词压进 base。原文不经 tags/权重解析；中文需 V5。已有发送前排字开关和 raw 的边界保持，详情见 [NAI 原生文字生成](docs/NAI原生文字生成.md)。

以下入口有不同的处理边界：

- `/anm 无优化` 保留所给提示词，不拼接质量词、画师组、画风或固定角色信息，也不执行内容 tag 清理。
- `/anm 多人 <描述>` 是保留的 2–4 人兼容模式，使用独立的多人规划和校验流程；日常多角色请求建议直接使用普通 `/anm`，以获得逐角色档案和衣柜处理。
- NAI `-r` 保留第一次意图规划与本地角色/衣柜证据，第二次 LLM 直接返回全局提示词、各可见实例的完整提示词与坐标，不再先写七字段再额外拆分。同次写作会复核完整画面语义、位置、tag 归属和 `source# / target# / mutual#` 方向；主机检查同动作双方配对；无法确认的动作组仅移除方向标签并记录诊断，保留普通动作与自然语言，不因配对问题重写或停止生图。它只适用于已配置 `NovelAIGenerator` 的优化模式，不能与原样模式合用；布局结构无法使用时停止提交，遗漏名词映射的独立 tag 不会阻断生图或触发整份重试。补齐范围见 [NAI -r 重构后功能补齐审计](docs/NAI-r重构后功能补齐审计.md)。
- `/anm 改图 <要求>` 需要附图或引用图片，并在配置中开启实验性图生图。放大和去背景仍未作为稳定功能提供。

提示词模式、角色优先级和 NAI 配置分别见[提示词与角色画风](docs/prompting.md)、[角色与服装配置工作流](docs/角色与服装配置工作流.md)和[配置说明](docs/configuration.md)。

中文 `-r` 请求的全局文本会说明整体构图、位置和互动，各角色框保留自身可见信息的中文；与档案一致的已识别中英文外貌不会再统一删除。普通身体状态词按身体部位所有者分配，例如“手在嘴里”属于嘴里有手的人，不能因为另一人是伸手者就复制到其角色框。写作者还会核对中文与 tags 的一致性，未要求照明时不额外补光，明确无光时不增添光源。

## 可选配置

- **千代预设：** 在配置页选择千代base、千代aesthetic 或千代turbo，可一并应用对应画师组、模型与采样设置。预设会把狐莉加入可识别角色列表，但只有请求中提到她时才使用。切回“未启用”可恢复启用前的基础配置。Turbo 工作流和低 CFG 约束见[版本变体](variants/README.md)。
- **角色与衣橱：** 固定角色只适合存身份和稳定外貌；命名服装、角色自有服装变体与别名可在词库中分别维护。具体规则见[角色视觉档案与服装优先级](docs/角色视觉档案与服装优先级.md)。
- **联网搜索：** 可在 AstrBot 全局配置中提供 Tavily key，辅助补充冷门角色或服装证据。视觉模型反推则需要配置可识图的模型。
- **会话打码：** 插件页面可按群聊或私聊会话开启发送前图片打码，默认关闭。它使用仓库中的 `autofilter2.json`，需要相应 ComfyUI 节点和检测模型；失败时不会把未打码原图发回聊天。安装要求见[配置说明](docs/configuration.md#按会话发送前打码)。
- **权限与限额：** 可配置允许/拒绝用户、每日次数、发送图片数量和输出保留天数；配置页还可添加多对屏蔽词组，每对跨组命中时拒绝生成。详见[配置说明](docs/configuration.md)。

文生图文件保存在 ComfyUI 的 `output/astrbot/日期/请求者用户ID/` 下；插件也会记录逐任务状态以便排查。内置与自定义工作流的 `SaveImage` 都使用这一用户目录。

## 排查与文档

如果 `/anm` 没有响应，先确认 AstrBot 收到了消息；如果显示 ComfyUI 离线，检查 `comfyui_base_url` 是否能从 AstrBot 所在机器访问。已生成但未发回聊天时，检查 `send_result_to_chat` 和平台适配器日志。更多错误标记与检查方法见[故障排查](docs/troubleshooting.md)。
