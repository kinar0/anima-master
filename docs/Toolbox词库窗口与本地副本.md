# Toolbox 独立词库窗口与本地副本

用户在 2026-10-19 明确要求将词库搬进插件，并参考 Toolbox 增加独立维护/翻阅窗口。此前运行时直接读取桌面 Toolbox 发布目录；本次复制所需的四个数据文件到插件自己的 `data/toolbox/tagdb`，原目录保留。复制有 SHA-256 核对和本地来源清单；不复制应用、账户、角色特征 CSV、wiki 详情、图片或依赖。本机副本是忽略的运行数据，没有加入 Git，也没有因此确认第三方数据可公开分发。

本机已完成复制并将持久配置的 `toolbox_vocabulary_path` 改到插件内副本。按用户自行登录/测试的安排，本次没有登录管理页面、使用管理凭据或调用管理接口重载；**请在 AstrBot 插件页重载 Anima 插件一次，再刷新详情页，打开“Toolbox 词库”**。重载后才会加载新的维护接口与数据路径，后续词条保存不需再次重载。

## 入口与操作

AstrBot 插件详情页 → **Toolbox 词库**。这是独立页面，与“服装词库 / 名词翻译”和“候选审核”分别保留。

也可直接使用兼容入口：**侧栏 Anima → 原服装词库顶部“Toolbox 词库” → 维护窗口**，窗口顶部可“返回服装词库”。有未保存的衣柜、名词或审核草稿时先保存或放弃，再切换；Toolbox 草稿同样受保护。这个入口沿用同一个受保护的页面与登录桥接，不要求新增登录，也不改变侧栏默认页。

兼容资源位于 `pages/wardrobe/toolbox/`，由 `scripts/toolbox_compat_entry.py` 从独立窗口资源同步生成；修改原窗口脚本/样式后需运行该脚本同步。回归使用管理面板真实的页面资源改写逻辑，核对往返链接和脚本/样式均保留同一页面的访问票据，避免受限框架中的跨页跳转失效。

入口兼容修复：AstrBot 侧栏及插件列表的快捷入口只打开按目录名排序的首个页面。新增窗口的内部目录改为 `pages/wardrobe_toolbox`，让原 `pages/wardrobe` 继续排在第一位；侧栏仍进入包含角色衣柜、通用套组、名词翻译、审核、批量翻译及打码设置的原页面。Toolbox 从插件详情的页面组件中独立打开，显示名仍为“Toolbox 词库”。旧的 `/toolbox` 页面地址需从详情页重新打开，收藏应更新为 `/wardrobe_toolbox`。本次不修改管理面板，也不改变原服装页文件或数据。

- 左边按 Toolbox 分类树翻阅，中间按中文别名、英文 tag 或短释义搜索，结果分页显示，每页 30 条；覆盖全部加载的 general 通用词条。
- 右边查看别名、短释义、误读提醒和易混词，复制 tag，编辑中文别名、释义、辨析及分类。
- “本地试查”使用实际 Toolbox 参考服务的筛选与否定边界，显示候选及匹配分数，不调用模型、不提交图片，也不混入原有手工名词映射。分数不是正确率或生成概率。
- “新建词条”需要合法英文 tag、中文别名和释义。停用词条后，该词不再参与 Toolbox 自动候选；原有手工名词映射仍由其自己的配置决定。
- “恢复原始值”撤销该词的本地覆盖；新建词没有原始条目，恢复后从本地新增集合移除。每次保存前自动留存原维护记录，可从维护历史恢复。
- 未保存时切换词条、翻页或刷新会提示先保存或放弃。保存期间暂停编辑；并发版本冲突保留草稿并拒绝覆盖。

## 存储和生成契约

`tags_index_v2.json`、`tag_gloss.json`、`tag_browse.json`、`tag_deprecated.json` 保留原始内容。`local-source-manifest.json` 记录来源和散列。`local_overrides.json` 单独保存本地维护；每次保存前的内容留在 `maintenance_history/`。维护只写配置指定的词库目录，网页请求不接受任意文件路径。

页面与 PromptPipeline 共用同一 `ToolboxVocabulary` 快照、锁及文件版本缓存。修改后的中文别名替换该词全部原中文触发别名，包括上游 full/short/nick 形式；其他语言原始名称保持。释义、分类与停用按词条覆盖，新建条目同样受限。保存原子替换维护文件后重新建索引，下一次检索生效，无需为每个词重新加载插件。

只修改释义、分类或停用状态而未改变中文别名时，保留上游原有的 full/short/nick 权重。易混词名称保留上游可读形式（例如 `body blush`），不强迫它成为单个 canonical tag；生成参考仍沿用原有的 tag 格式与预算检查，维护记录不会替标签建立额外权限。

本次只改变本地参考数据的可维护性。LLM1 → 身份/外貌/衣柜权限 → Toolbox 有预算的可选参考 → 原有 LLM2 → 后处理 → ComfyUI/交付的流程保持。字段不进入 hard tags 或身份/衣柜授权。默认参考预算和无命中不增加内容的边界保持；不删原有提示词职责、不增加模型阶段。保存了某个释义不保证它会被当前请求选中。

释义、误读和每条辨析各不超过 100 字符；同一词最多 60 个别名/分类、8 条辨析。生成仍使用自己的候选及总字符预算。超过限制时拒绝保存或按原预算舍弃完整可选条目，不截断用户原文或规则。坏维护文件与坏原库一样，使该参考层降级为不可用，不破坏原生成流程；维护页报错而不覆盖损坏资料。

## 本地复制工具

`scripts/toolbox_copy_local.py --source <原有 resources/tagdb 目录>` 默认复制到该插件目录的 `data/toolbox/tagdb`。目标已存在且内容不同则停止，不覆盖维护后的文件；也不替换已有维护记录。复制完成后将 `toolbox_vocabulary_path` 指向新目录并保存配置。已有插件安装需要重载一次以加载新页面与接口；后续词条编辑不需重载。

页面布局参考 Toolbox 的“分类树 / 词条列表 / 中文说明”思路，HTML/CSS/JavaScript 在本插件中独立实现；现有检索移植来源与声明见 `third_party/llm_nai_toolbox/NOTICE.md`。代码许可声明不自动覆盖外部词库资料。
