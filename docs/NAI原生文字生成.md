# NAI 原生文字生成（2026-10-15）

本功能让 NovelAI 将文字直接画进图中的牌子、衣物、字幕或气泡；它不调用 Pillow 排字。普通 `/anm` 和 `-r` 都保留画格、角色实例和文字位置。优化中的原生文字请求自动复用已有逐实例写作者，不增加正常第三次模型调用；没有文字需求的普通七字段流程不变。原有身份、衣柜、外貌、可见性、双语和互动权限继续执行。

## 使用

当前工作流须包含 `NovelAIGenerator`，中文使用 V5，例如仓库的 `nai_api.json`。

```text
/anm 一个女孩举着木牌，木牌上写着“欢迎光临，C#社！”，文字只在牌子上
/anm -r 左边千早爱音说：“你好！”；右边丰川祥子回答：“Hello, Anon!”；台词各放在自己的气泡里
```

多格漫画也可不写 `-r`，例如：

```text
/anm 两格漫画，左上A格：千早爱音：“你好！”；丰川祥子：“等等！”；左上A格右上角旁白：“放学后。”
右下B格：千早爱音：“再见！”；右下B格左下角旁白：“第二天。”
```

输出保持三个人物实例：A 格爱音、A 格祥子、B 格爱音。前三条对白分别放在各自实例末尾的 `Text:`；两条旁白保留各自的画格/角落说明，文字进入 base 尾段。不能按角色名把两格爱音合并，也不能把旁白当成角色。相同台词出现两次也按两个出现编号处理。

自动提取处理有写字/显示/说话上下文的引号原文、明确脚本及 `标签：“原文”` 形式。冒号标签本身不证明是台词，writer 结合完整原文区分角色对白、旁白或服装/画面条件；只有这类歧义候选可标记忽略，明确要求的文字不能忽略。普通无标签服装引号和明确否定不会自动成为文字。复杂否定、间接引用或没有明确边界的“写一段文案”等仍不是通用语义抽取；需要确定原文时给出引号文字或原生尾段。不自行翻译、改成大写、缩写或截断。

也可明确指定原生 `Text:` 尾段，尤其适合多行文字。它必须在请求最后；段落之间留一个空行：

```text
/anm 一个女孩举着木牌，木牌上是下面的文字。 Text: 欢迎光临
今天也要开心！

C# Club
```

`Text:` 后面全部视为要画出的原文，不能再写尺寸、画风、说明或其他 tags。用引号写出的普通 `“Text: Hello”` 不会提前开始尾段。`#` 只在引号和原生尾段外分隔手工 tags，因而文字中的 `C#` 不会被拆走；手工 tags 插在最终 `Text:` 之前。原样/关闭优化仍不自动提取自然语言引号、不添加文字 tags；直接提供的原生尾段保留换行和标点。

## 模型限制

按 [NovelAI Text Rendering](https://docs.novelai.net/en/image/textrendering/)：

| 模型 | 文字语言 | 最长原文（含空白与换行） |
| --- | --- | --- |
| V4 / V4.5 | 英文 | 118 字符 |
| V5 Curated | 英文、中文、日文等 | 374 字符 |
| V5 Full | 英文、中文、日文等 | 750 字符 |

宿主按最终拼成的原文计数；超长、空尾段或旧模型收到非 ASCII 文字时，在提交前报错，不偷偷删字或换模型。V4/V4.5 的检查是保守的 ASCII 限制，带弯引号或重音字符也建议改用 V5。NAI API 本身仍是普通 prompt / `v4_prompt.caption.base_caption`，没有新增文字 API 参数。

官方说集中到 base 可能可靠，同时明确允许角色框使用 `Text:`，多角色文档也有把台词放在角色框的示例。集中到 base 不是强制规则，不能因此丢失漫画归属。本插件将对白绑定到具体实例尾段，旁白/无主文字才使用 base，并通过实际 prose 指明画格、位置、颜色和样式。NAI 没有在这些请求节点中提供独立的旁白框坐标接口；旁白位置是自然语言条件，不是精确排版保证。官方还指出质量预设中的 `no text` 会影响短文字。优化模式加入文字/语言 tags、清理正向独立 `no text`；只要 base 或任一实例有原生尾段，提交时便移除负向独立 `text`、`no text` 和中英日文字 tags。其他负向仍保留，不泛删 `watermark`、`signature` 或含 text 的短语。

若开启已有的 `comic_dialogue_enabled`，明确漫画对白继续交给原来的发送前排字流程，自动原生对白提取关闭，避免同时画两份；牌子等独立文字仍可使用原生功能。显式 `Text:` 属于用户直接要求原生生成，不受该自动提取开关影响。混合原生文字与排字对白时应在原文中明确区分。

## 数据路径与维护边界

1. `PromptPipeline.build` 读取当前 NAI 工作流模型，从追加参考上下文前的用户请求复制文字；搜索、引用或参考图里的字不自动成为本次文字需求。
2. `nai_text.py` 保存每次出现的原文、不可变 id、字符位置和原始上下文；同字台词也不去重。文字编号的来源由宿主提供，不要求 writer 重新拼接/抄写原文证据，也不接受它覆盖来源。LLM1 的服装/外貌协议不变。
3. 原生文字的 LLM2 使用已有实例 JSON，并新增 `text_regions`：每个 id 恰好对应一条 `kind / character_index / panel / placement`。实例索引对应最终 characters 数组，不能按名字或出现次序猜；旁白/画外对白用 null owner，物件按是否持有/穿着确定作用域。画格短语须来自该原文上下文；最终实例 prompt 会包含完整画格位置说明，raw 已明确写成另一格时视为矛盾。跨格不能复用同一实例。位置说明必须含该 id 自己的 token。缺项、重复 id、无效实例、虚构画格和绑定层的作用域错误合并进原结构修复一次，仍失败停止。
4. 写作者在实际角色/全局字符串及位置说明中用 `NAILITERAL...TOKEN`；人物对白不能复制到 base 或其他角色。唯一原文直接以引号出现时也会保护，重复同字原文需要不同 token。绑定表已合法但 writer 在错误 prompt 多复制了一个已知 token 时，宿主按已接受的归属表把越界引用降为不含台词原文的普通描述，保留其余动作/画面句，记录 `nai_dropped_text_references`；不改变绑定、不猜新 owner，也不对整份有效布局反复重写。身份、外貌、衣柜过滤后，完整位置说明追加到正确的实际 prompt，再恢复加引号的文字；防止文字自身的 `Text:` 提前开始尾段。各实例只拼自己的文字尾段，base 只拼无主文字，按原始出现次序排列，同作用域多段用空行分隔。不猜写缺失台词，不给旁白创建人物；无人物标题的空实例计划会清除工作流导出的示例角色输入。
5. 自定义工作流适配器写入 base 及独立的角色转换节点，对所有尾段的合计原文按实际 NAI 模型校验长度/语言，不能分散后绕过上限。六个转换节点只转换各自 `Text:` 前的视觉权重，尾段的逗号、空格、括号、`::`、`#` 和换行保留。发送前补手工 tags 仍在 base 的尾段之前；角色尾段不会再被后续外貌/衣柜清理修改。
6. 生成、history、下载与聊天交付沿用原路径。本功能没有新增生成重试、OCR 或发送后排字步骤。

新增指引只补充文字职责，原有英文 tags / 中文 prose 并存、可见实例、方向动作、位置、角色外貌和衣柜权限全部保留；不能借这次改动精简原任务书。文字出现在原始请求里不表示它的内容自动授予外貌或服装修改权限。

## 验证和能力边界

离线测试在 `tests/test_nai_text.py`，覆盖普通/`-r` 的多格同名角色、每格不同台词、两处旁白位置、重复同字台词、无人物标题、错误绑定重试与停止，以及 raw、参考隔离、特殊字符、工作流传递、负向冲突和合计上限。转换节点测试在扩展的 `tests/test_converter_text.py`。

`tests/live/test_nai_text_live.py` 调用真实 provider，保存原始输出、后处理和最终 prompt，覆盖招牌、双人对白、不写字及普通/显式 `-r` 的两格漫画。用 `ANIMA_RUN_LIVE_LLM_E2E=1` 启用，`ANIMA_LIVE_REPORT_DIR` 指定目录。本次分格修订记录在 `diagnostics/nai-text-scoped/`，包括初稿失败；此前 `diagnostics/nai-text/` 是旧全局尾段方案的验证，不能用于宣称漫画归属已经验证。匿名角色仍可能有既有候选调用，不能假定 writer 总是第二次调用。

早期一次举空白牌的真实反例被原有方向校验拒绝：writer 将单人 `holding_sign` 写成孤立 `source#holding_sign`，修复后仍无对端。文字提取没有触发；失败证据独立保留。当时测试另用放在人物旁边的空白牌隔离互动问题；2026-10-16 起按下节规则对辅助方向标签降级，原失败记录仍保留。

这些验证证明文字进入最终请求时的保留与归属，不证明生成图片已经正确写字。没有执行 NAI 图片生成或 OCR 验收。模型仍可能漏字、错字、气泡错位，复杂多格与长段落尤其不可靠；“原文稳定传递”不能表述成“图中文字百分之百正确”。


## 2026-10-16：方向标签降级与文字硬校验分离

上文举空白牌被互动配对拒绝是历史记录。当前孤立的 `source#holding_sign` 只会作为不确定方向提示移除；普通 `holding_sign`、中文举牌动作、位置及文字原文继续保留，不为单人动作新增接收者，也不因方向配对重写或停止。文字的缺项、重复、跨格和错误归属仍单独修复一次，失败停止；初稿或文字修复稿均执行同一方向降级，方向问题不会占用文字修复机会。
