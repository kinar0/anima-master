# 分格文字与角色实例绑定验证

2026-10-15，修正“所有文字都塞入 base”的设计。官方明确允许角色 prompt 使用 `Text:`；集中 base 是可选建议，不能代替漫画的画格/实例/位置关系。

## 最终行为

- 优化中的 NAI 文字请求复用既有 LLM2 实例写作，普通入口自动启用，未增加正常第三次调用。
- 宿主保存每次原文出现的不可变 id、原始位置与上下文；模型用 `text_regions` 分配画格、最终实例索引/旁白及位置句。角色身份名单不是实例数量，同名跨格必须重复建框。
- 人物对白只在所属实例的 Text 尾段，旁白等无主文字在 base，且在实际 prompt 中保留画格/角落位置句。绑定表错误修复一次仍无效则停止，不按名字或数组次序兜底。
- 有效绑定下的额外越界台词引用通过 owner 表投影，保留画面描述并记录移除，不改变归属。最终各尾段才恢复原文；所有尾段合计受实际模型上限约束。
- 原有画面完整性、英中双语、方向配对、服装/外貌/可见性规则保留。没有文字需求的原七字段与实例流程不变。

## 证据

最终离线相关回归覆盖文字通道、普通/实例 writer、衣柜策略、手工尾缀、自定义工作流、已有排字与 CLI：387 passed，仅有既有 audioop 弃用提示。

`nai_text_comic_False.json` / `nai_text_comic_True.json` 是普通入口和显式 -r 的真实 DeepSeek 记录。请求包含 A 格爱音和祥子对白、A 格右上角旁白、B 格爱音对白和 B 格左下角旁白。验收三个人物实例、三个独立对白尾段、两处旁白的位置句与 base 尾段。`conversion_check.json` 检查这两份记录的 8 个实际转换输入，确认权重转换后每个尾段逐字保持。没有执行 NAI 图片生成、OCR 或聊天平台交付。

初轮/中间记录均保留，不以成功覆盖失败：

- `*_initial.json`：模型将不连续的角色/画格来源拼成一句，导致严格来源拷贝失败。改为宿主的不可变原文位置，模型不再重抄来源；并非放宽任意来源的归属权限。
- `*_second.json`：采用宿主来源后的成功记录。
- `*_third.json`：一次缺少 raw 的完整画格字面短语；另一次把同名 A/B 格合并。前者最终位置句可保持信息，不应仅因同义/省略字面标记重试；后者仍作为真实结构错误拒绝。
- `nai_text_comic_True_fourth.json`：模型额外把已知台词复制到 base/另一实例。根据有效 owner 表做确定性引用投影，避免再次全量重写引入合并问题。

真实模型仍可能返回需要修复或被拒绝的结构。验收是“有效结果保留正确的文字归属，错误结构不提交”，不是“每次调用都成功”或“生成图已达到精确漫画排版”。旁白位置是自然语言条件，当前节点没有独立旁白框的精确坐标 API。
