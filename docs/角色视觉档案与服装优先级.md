# 角色视觉档案与服装优先级

本文记录角色识别、Danbooru 视觉档案学习和服装修改的现状，供后续维护时参考。

## 当前流程

1. 语义规划 LLM 从用户请求提出角色、作品、姿势等候选。
2. 本地 `danbooru-tags` 验证候选；括号中的英文角色别名和作品名会被确定性提取。例如 `复仇者（revenant）` 与 `《黑夜君临》（Elden Ring Nightreign）`。
3. 已确认的目标角色会从 Danbooru 帖子采样，学习默认服装 tag 与稳定外观 tag（例如发、瞳、角、耳朵、尾巴、翅膀、伤痕），并保存为角色视觉档案。
4. 最终提示词阶段注入角色 identity、学习到的外观锚点和适用的服装 tag。

本地词库只验证或筛选候选，不能从中文俗称自行推断角色。对于训练语料覆盖不足的新作品角色，应配置本地别名映射，例如 `哈吉蜗=revenant_(elden_ring)`。

## 服装意图

| 用户表达 | 当前意图 |
| --- | --- |
| `官方常服`、`官方默认服装`、`原作服装`、`默认服装`、`标准服装` | 使用角色视觉档案中学习到的官方默认服装。 |
| `常服`、`私服`、`居家服`、`日常便服`、`随意生活服`、`休闲穿搭` | 抑制官方默认服装；保留角色外观锚点，并使用宽泛的 `casual` 意图。 |
| `白色卫衣和牛仔短裤` 等具体衣物 | 应作为用户显式服装约束。 |

“常服”在中文里存在歧义。当前裸 `常服` 按生活私服处理；需要原作服装时请使用 `官方常服` 或 `默认服装`。

## 设计上的优先级

目标优先级为：

1. 用户明确的服装修改；
2. 本次请求的命名套装或服装迁移；
3. 角色官方默认服装 profile；
4. 角色稳定外观 profile；
5. 最终 LLM 的自由补全。

例如：

- `官方常服，但是没穿外套`：保留默认套装其他部分，移除 `jacket`、`coat`、`cloak`、`cape` 等外套槽位。
- `官方常服，但是黑色外套`：将外套槽位替换为黑色。
- `随意生活服，但是黑色系`：不使用官方默认服装，保留角色外观，并生成黑色系休闲穿搭。

## 已知不稳定点

截至本文记录时，“基于官方服装的局部修改”尚未在普通自动识别角色请求中完全稳定。

- 服装补丁解析依赖明确的目标角色绑定。固定角色、服装迁移目标通常可绑定；仅靠自动语义识别的单角色请求可能没有绑定到补丁解析器。
- 当前补丁语法稳定支持“颜色 + 具体衣物槽位”（如 `黑色外套`、`裙子改成黑色`）和移除具体衣物（如 `没穿外套`）。`黑色系` 这样的全套风格表达尚未转为确定性补丁。
- 即使确定性层已产生服装 tag，最终提示词 LLM 仍会写自然语言细节；清理器会尽量阻止冲突 tag，但不能把第二阶段 LLM 当成绝对可靠的服装解释器。

因此，当前不应承诺以下表达已经稳定：

- `官方常服，但是黑色系`；
- 普通自动识别角色下的 `官方常服，但是没穿外套`。

## 后续改进方向

1. 将已本地确认的单一目标角色自动绑定为服装补丁对象。
2. 为“全套配色/风格”增加确定性 patch，而不是让 LLM 推断 `黑色系`。
3. 在补丁生效时，以“角色外观 + 修改后的服装 + 用户明确衣物”为严格白名单，避免最终 LLM 补回原服装。
4. 将页面中的“档案类型”升级为自由档案名称加服装意图，而不局限于默认、夏季、冬季和舞台。
