## 用户纠正后的核心结论：来源 canonical tag 被抑制

上一轮把重点放在组件误删、面具和人数，并据那些断言宣布修复，漏验了用户最关心的来源 tag，结论不完整。`include_source_anchor` 在有任何 `outfit_source` 时固定为 false（Git blame 对应 2026-08-26 的 `77f6656b`），来源因此不进入通用 hard-tag 通道；此前上下文还有“context only; do not emit as a hard tag”的抑制说明。2026-10-08 的 `1b91d16` 仅为明确 cosplay 加 `_(cosplay)`，普通“穿 C 的衣服”仍没有任何来源锚点兜底。正常单人出图记录缺少所选来源的独立 canonical tag；15:14:28 虽出现 Mortis tag，却被错误放进可见角色名单、变成两人，不是正确的衣服来源绑定。组件和删改通过不等于衣服来源正确。

本轮按用户明确要求恢复已确认、已绑定来源的原始 canonical tag：普通进入本人的实际 Details，NAI 进入本人的实际角色 prompt；单个来源锚点由已有衣柜绑定保证保留，修改衣物不再令它消失。来源不进入可见 roster/人数、不带入 donor 外貌；未知/未绑定/纯外貌参考不产生来源 tag；原有显式 cosplay 后缀独立保留。单个来源锚点恢复不改变“完整组件不由主机注入”的契约。`tests/test_outfit_source_anchors.py` 覆盖 writer 完全遗漏来源 tag 的普通和 NAI 双人反例，并同时验收对应穿着者、人数、面具删除与不应匹配的来源。此前拒绝来源 tag 的老断言已替换为“来源保留且用户修改保持”的断言。

本轮最终验证：540 项相关本地回归通过；[live-source-anchors/](live-source-anchors/) 的五个完整真实模型用例全部通过，直接把最终文本按独立 tag 分割后检查 canonical 来源，而非姓名提及、组件、衣柜命中或任务书。Mortis 脚部焦点、Oblivionis 剪裙及 NAI、其他人物局部改上衣、双人各自借不同来源均保留对应原始来源 tag；人数不增加、修改仍生效。仍未提交新图片或重载插件。

## 修改与职责对照

请求路径：命令分发 → generation_task 拆 raw/# → PromptPipeline → LLM1 → 本地身份/供衣证据 → 有效衣柜/外貌权限 → 普通七字段或 NAI 逐实例 LLM2 → 同权后处理/最终组装 → ComfyUI 工作流 → history/下载 → 聊天交付。本次改变前中段规则，不改工作流提交与交付。

| 职责 | 修改 | 保留的边界 |
| --- | --- | --- |
| LLM1 局部改衣 | 新增 modify；局部保留误报全身 keep_only 时进入原有一次修复；仍错则不执行该破坏性指令 | 原文继续交给 LLM2；无宿主猜测新衣物或自动补全；真正的全身 keep_only 继续有效 |
| 聚合槽位 | keep_only 使用与其他补丁一致的 lower_body.all 分类 | 仍仅根据已选档案操作 |
| 可见身份 | 所有供衣名字出现都位于已接受 clothing 引用内时，不强制来源本人出场，并要求 planner 修复多列人物 | 有独立出现的来源仍保留；不按任意名字猜可见性 |
| 构图权限 | focus 本身不证明其他部位在画外；局部特写才可结合焦点确定裁剪；full body 的 focus 不裁掉其他衣物 | 明确上半身、膝上、只拍局部仍裁剪；不自动追加全身 |
| 配饰删除 | 兜底识别没有/没戴/不戴/摘掉等已支持服装词；补齐帽子等 headwear 名词 | 逐角色、同名逐实例边界沿用；另一人缺席要求不传播 |
| 人物 prose 过滤 | 本人已选具体组件保护其匹配片段，另一人的通用 brooch 不删除本人的 green_brooch | 明确删除、其他人的专属衣物仍过滤；不补标签、不授予整套衣柜 |
| NAI 修复 | 明确文字登记表不重构 source_text 的规则不豁免 identity_review 的原文依据；缺 donor 要补审核 | 完整原任务书保留；仅原一次修复，不放宽缺人/来源升级/引用校验 |

没有精简现有提示词。普通 LLM1 新增 modify 与 keep_only 的职责说明、局部改裙反例和括号配饰缺席要求；原人数、实例、身份、外貌修改协议继续保留。NAI 仅澄清修复任务的两类 source_text，原双语层、逐角色服装/外貌、可见性、互动方向、身体所有者、坐标/接触、文字归属与同次复核职责不变。原样、手工尾缀及旧多人兼容路径保持原边界。
