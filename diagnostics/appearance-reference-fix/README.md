# 外貌参考与额外条件膨胀修复（2026-10-19）

## 结论与根因

问题发生在提示词构建链路，不是 ComfyUI 在提交后自行加词。修复前 18 个相关历史任务中有 17 份 PNG，可从内嵌 workflow 核对实际输入；全部与任务保存的最终文本及手工尾缀一致。历史证据保存在 [原审计](../anon-hairstyle-audit/README.md) 与 `evidence.json`；当前代码复放另写 `evidence-current.json`，不覆盖基线。

这不是单纯的长度问题，主要是几个边界叠加失效：

1. LLM1 没有独立表达外貌来源的字段，偶尔将借发型解释为借衣，或把仅提供参考的人列入必须出场的名单。普通写作者又会被名单校验强迫补人。
2. LLM2 看到了来源的完整衣柜，却未得到其被借用维度的已有准确事实；于是用近似半扎、辫子或发髻猜造型。
3. 后处理将发型中的 `tail` 判为身体尾巴，删掉已授权发型；新发型的发带又可能被来源旧衣柜的 stale 集合删除。
4. 中文大头照没在写作前限制默认衣柜；领带/袖子未跟随躯干裁剪，裁剪也可能丢失禁止记录或把空参考误判为缺档案，诱发服装补全。
5. 普通模板允许自由光影/特效和整幅画面 Nltags 复述，核心特征被错误近义项、画外衣物与装饰反复条件化。质量、画师和手工尾缀则属于另外的宿主通道。

## 通用修复

- LLM1 `appearance_changes[].reference_character` 与 `clothing_source` 分离，来源必须在该修改的原文引用内。只有名字出现在他人的外貌参考短语中，不能成为强制可见人物；独立出场描述仍保留。失败修复后的可用子集也不能获得无依据衣柜/出场权限，完整原文继续提供给写作者。
- 来源唯一精确绑定本地身份后，只投影所指维度的已有事实。来源颜色、身体、服装与作品元数据不随发型迁移；未知或歧义只保留原句，不以相似名字选整份档案。来源另有独立可见角色或独立借衣时仍走各自权限。
- 对已表达的可见来源维度检查接收者自己的 Identity/Details 或 NAI 实例 prompt。只放共享 Tags 或分析不算完成。缺失事实复用原有一次 LLM2 修复预算，仍错停止，不由宿主补一整套标签。标签的空格、下划线、连字符分隔等价；不可见、独立改写、来源冲突的维度不强补。一般名词翻译继续是可选参考。
- 发型复合词和真正身体尾巴分开处理。发型修改允许相应实例自行选择发饰，不注入配饰、不开放整套衣柜、不抵消显式删改。多人和同名多格分别绑定。
- 写作前后复用构图裁剪，领带/袖子随躯干裁去；头部肖像不被隐式默认制服身份拉成全套展示。保留移除/禁止记录，空裁剪不误触发缺档案回退，明确命名套组和用户补丁仍受原有保护。
- 内置默认、普通 system 与运行时自定义任务书明确聚焦范围和 Nltags 的补充职责。保留创意/色气/动作需要的设计；不设固定 tag 配额，也不通过粗暴删除整句自然语言消除重复。NAI 双语、实例、动作和位置职责不变。
- 附带修复 raw 前缀及 `-r` 扫描对末尾 `::`、换行/标点的破坏。原样入口不进入新语义校验。

扩展动作场景仍有一次模型物理语义冲突，不能宣称所有提示词契约已被自动证明。普通 Nltags 也仍可能重组已有事实；最后主线中白底肖像多例已为空，原天空肖像和多人仍有复述。该边界依靠写作规则与既有精确去重，不是任意语言的完备语义去重器。没有扩大主机粗删，以免损坏关系、动作和空间含义。

已保存的证据不包含 provider 密钥。未改生产设置、角色档案、画师或质量前缀；未重启插件、未做像素级对照图。因此文本链路修复已完成，成图改善仍需重载插件后以相同模型/种子对照，无法从这些文本测试量化各因素的视觉贡献。
