## 4. 首版范围与实现形态

| 部分 | 首版用途 | 边界 |
| --- | --- | --- |
| `search.ts` 的检索与评分 | 复用归一化、候选预筛、字段加权和排序，做本地候选检索 | 分数只排序，不证明含义、身份、穿着者或后端支持 |
| `gloss.ts` 的释义结构 | 读取短释义、字面误读、相近词区别和废弃提醒 | 不完整搬入上游提示词；不把中文释义当触发别名 |
| `browse.ts` 的分类数据访问 | 补充有限的相关分类候选 | 不常驻全分类目录，不复制默认整页 12000 字符/至少 30 条的返回方式 |
| `tags_index_v2.json` | 读取所需类别和名称候选 | 首版优先 general；不覆盖现有身份 resolver，不把全部别名导入单值词库 |
| `tag_gloss.json`、`tag_browse.json`、按需的 `tag_deprecated.json` | 对命中候选做解释与辨析 | 缺失或损坏时诊断并沿原流程降级；不增加模型查询重试 |
| `tags_detail_v2.json`、角色特征 CSV | 首版不作为必需依赖 | 不默认载入完整 wiki/全角色外貌衣服，不作为第二套角色/衣柜权限 |

实现优先采用 Python 适配/移植纯检索逻辑，使用当前 AstrBot 运行环境，不要求启动 Toolbox、安装 Electron 或新建常驻 Node 服务。保留最小上游参考文件和来源清单；用同输入对照确认评分/排序，涉及 JS/Python 字符处理与浮点差异时记录并验证，不声称未经对照的逐项等价。若必要依赖使此路线不合适，再报告具体原因，不默默引入整个应用。

数据读取使用可配置来源路径及缓存。读取/解析不阻塞 AstrBot 主事件循环；不逐次重建大索引，版本或文件改变后明确失效。将加载耗时、内存和请求检索耗时纳入验收。

## 5. 插入现有请求链的位置

```text
命令入口 / 原文与参考上下文 / raw 和 # 边界
  → 现有 LLM1 逐角色意图与修改
  → 现有 resolver、角色/命名服装证据、衣柜和外貌权限
  → 本地 Toolbox 检索与释义补充（有预算的可选参考）
  → 原有 LLM2：普通七字段或 NAI -r 逐实例 JSON
  → 原有确定性权限过滤与最终组装
  → 原有 ComfyUI 提交 / history / 下载 / 聊天交付
```

检索优先使用用户明确的 tag、现有名词命中，以及 LLM1 已绑定的衣物/外貌修改原文；普通动作和镜头从原文中做有限本地候选检索。不能假定现有 LLM1 已输出完整动作/场景概念，也不为覆盖检索把它扩成巨型协议。没有本地证据或歧义过大时保留原文交给 LLM2，不为了命中而猜衣服、身份或作用域。

保留原文位置、否定、角色/实例绑定和来源。多义词保留少量候选及区别；未绑定的一般概念不得擅自分给人物。匹配不提供 hard-tag、衣柜选取、身份建立或强制补入权限，模型不采用时不补回、不触发重试、不阻断提交。

首版普通优化和 NAI `-r` 共用参考服务与预算规则；不向 raw、关闭优化及手工 `#` 尾缀注入；旧多人兼容和图生图先核对消费者，未覆盖的入口保持原行为并明确标注。Turbo 不是顺带重写范围。

## 6. 控制任务书体积，不删现有功能契约

1. 接入前按修复后的实际拼装结果记录 system、固定规则、用户原文、身份/衣柜/外貌证据、名词参考、引用上下文及修复消息各自的字符/token。历史六格样例 system 3378、正文 21071 字符只是对照材料，不代表当前所有路径。
2. 将现有名词参考和新增候选按 canonical 合并成一个词汇参考区，已有明确参考可补必要短释义，避免再追加一套同词列表。相同 tag 的释义只出现一次；不同实例的归属仍分别保存，不因为去重而合并穿着者或修改。
3. 常见且明确的词通常无需长解释；优先给字面误读、多义词和易混词提供短释义/必要区别。匹配分数、完整别名列表、索引匹配字段和来源长文留在本地诊断。
4. 新增参考区有独立硬预算，预算覆盖标题、候选和辨析的全部渲染文本，不允许“最少条数”突破。试验起点：全请求最多 8 个概念、每概念最多 2 个候选、参考区最多 1200 字符；这是待评估的起点，不是已证明安全或足够的产品阈值。
5. 没有匹配则增量为零。超过预算按相关性删除完整可选条目，不截断用户原文、必需规则、精确修改、台词或角色绑定，也不截断到只剩 tag 而丢失消歧所需的解释。复杂请求优先保障原语义，不按人数无限复制释义。
6. 若目标 provider 有可靠 tokenizer，另外记录 token 增量并据此调整阈值；没有时明确只测字符和字节，不把通用比例当精确 token 或费用。预算只限制新增可选资料，不把旧参考意外扩大后计作“未增加”。
7. 保留现有语义阶段、写作者职责和结构修复预算；不增加模型主动检索工具循环、翻译调用、嵌入服务或新增语义复核调用。既有结构修复仍可能发生，需分别报告，不能承诺每个请求总调用数永远固定。

## 8. 验收范围

- 检索：精确词、别名、相近拼写、CJK 归一、短词歧义、未知词、坏字段和缓存失效；与上游参考实现进行有区分力的评分/排序对照。
- 语义正反对：相机俯视/人物低头、连衣裙/半身裙、发型引用/借衣、发型中的 tail/真实尾巴、动作提及/否定、场景中的制服/实际穿着。示例用于验证通用边界，不新增角色或句子特判。
- 多人/多格：同名实例不同修改、共享服装、来源不独立出场、外貌引用不带来源衣柜、释义复用但绑定不合并。
- 预算：零命中零新增；可选参考始终不超硬预算；复杂请求无成倍重复；超额不删原文、权限、台词或既有职责。
- 流程：新增检索不引发模型调用或缺 tag 重试；普通/-r 均可关闭后回原路径；数据损坏不破坏生图主流程；raw/# 不受影响。
- 性能：记录实际发布版数据的加载耗时、常驻内存、检索耗时和任务书增量；先比较再决定是否扩充类别，不以一次最好结果保证性能。
- 真实模型：选定少量相同请求对比接入前后 raw、最终提示词、实例/衣柜归属、遗漏与重试。不因上下文未超窗、字符下降、合法 JSON 或纯替身测试通过就宣称语义效果等价。

不自动读取或外发真实聊天历史。外部模型或图片生成按本聊天届时已有的明确授权与工具审批执行；其他聊天的测试授权不挪用到本任务。无相应授权时完成本地和输入构造验证，列明未完成的模型/图片验证。

pytest 使用 AGENTS.md 指定的 AstrBot Python 3.12，首次调用即设置 core 的 PYTHONPATH，并带 `-p no:cacheprovider`。只运行与实际修改相关、能区分通用修复与反例的检查。

## 9. 停止或暂缓扩大范围的条件

并行修复尚未交付、基线仍漂移、组合检查有未解释失败时，不开始主链集成。无相关候选、预算不足或数据不可用时，直接沿原有请求处理，不用新增模型调用补洞。来源许可不足仅限制相应内容的复制/公开分发，可继续不受影响的本地适配工作。若候选只增加字数而未带来可观察收益，保持关闭或缩小范围，不以“已经搬入”作为默认启用的理由。
